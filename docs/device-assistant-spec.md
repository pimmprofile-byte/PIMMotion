# DeviceSeatAssistant — 개념/아키텍처 스펙 (PIMMotion 2번째 툴)

> PIMMotion의 두 번째 에디터 에이전트. 게임에디터(소프트웨어 설계)의 **하드웨어 짝** —
> 아두이노↔PC **시리얼 통신 규칙 · 코드 · 회로도/배전 도면**을 코워크와 대화형으로 설계한다.
> **정본 규격**: Drive `260502_플로직매뉴얼_장치통신표준_개정판` (기존 표준을 준수·생성).
> **전신 툴**: Drive `SerialTunner`(v0.4, 보드·핀맵·프로토콜·핸드오프) → 자체완결로 재구축.

---

## 0. 학습한 기존 시스템 (정본)

### 시리얼/보드 표준 (260502 장치통신표준)
- **듀얼보드 = Arduino Mega 2560**, 외형 동일 → **핸드셰이크로 식별**.
  - 보드→PC: `PIMM_input\n` / `PIMM_output\n`, PC→보드: `PIMM_ACK\n`. baud **115200**.
- **핀-ID 고정 매핑**: D22=ID_01 … D53=ID_32 (32ch). 입력=`INPUT_PULLUP`(활성 LOW), 출력=`OUTPUT`(부팅 LOW).
- **시리얼 포맷**:
  - 입력(보드→PC): **`IN_NN`** (NN=01~32, 디바운스 50ms, HIGH→LOW 천이 시).
  - 출력(PC→보드): **`OUT_NN_on` / `OUT_NN_off`** (멱등), 응답 **`OK!`**. PWM 옵션 `OUT_NN_pwm_VVV`(D44/45/46).
- **펌웨어 고정**(재플래시 금지) — 의미부여는 **PIMM_Registry**(핀↔디바이스). 명명 `Bl_/Var_`, MAP 100단위, 장치코드(입력 Btn/SW/SS · 출력 Rly/SSR/Dcv/Ltx/Mtr/Air/Lin/Fog).
- **전원/부하**: OUTPUT 보드 자체전원 부하구동 금지 → 외부 12V SMPS + MOSFET 모듈. GND 분리.
- PIMMplayer 측(Unity): SerialDevice/BoardHandshake/InputBoardController/OutputBoardController + EffectInterpreter(FLS/DIM/DKS/AIR).

### 연출·몰입 이론 (Plogic)
- **싱크레시스**: 장치 물리동작 ↔ BGM/SFX **0.1초 단위 동기**(몰입의 핵심).
- 5대 몰입로직(긴장·해소 / 미장센 / 싱크레시스 / 게이트웨이 / 페이싱). PIMMscape(방탈출 60~75분), PIMMUP(팝업 즉각 임팩트).
- 연출기기: 조명(Ltx)·모터(Mtr)·에어(Air)·포그(Fog)·리니어(Lin)·릴레이(Rly) 등 → 출력보드가 구동.

## 1. DeviceSeatAssistant 범위 (3영역)
1. **시리얼 통신 규칙 정의** — 위 표준 준수. 핀↔디바이스 매핑 + PIMM_Registry 생성.
2. **코드** — 보드 펌웨어는 표준 고정(재플래시 금지)이 원칙이나, **게임 전용 로직 보드(게이밍)** 등 커스텀 .ino가 필요한 경우 생성 보조(예: PIMM_LaserDodge.ino류). 표준 IO는 Registry만.
3. **회로도/배전 도면** — 두 계층: (A)보드 핀맵(논리) (B)배전함 물리배치(실측).

## 2. 3종 보드
| 보드 | 역할 | 방식 | 비고 |
|---|---|---|---|
| **인풋보드** | 물리신호 수신(버튼/스위치/센서) | 핀+GND, INPUT_PULLUP(활성 LOW) | 표준 IN_NN |
| **아웃풋보드** | 릴레이모듈 연출 구동 | 핀+GND → 부하(외부12V/MOSFET) | **SSR 사용 시**에만 핀+GND로 SSR 제어 로직 추가(극히 드묾 → 필요시만) |
| **게이밍보드** | 게임의 물리 인풋(버튼/스위치) 맵핑 | 핀+GND(인풋형) | **한 게임 시퀀스(SEQ#)에 해당하는 버튼끼리 그룹** — 이 그룹이 작업 기준. 게임에디터 시퀀스와 연동 |

- 게이밍보드 = 인풋보드의 게임 특화(시퀀스 그룹핑). 게임에디터 `combo_input_registry`(G1~G6)·SEQ#와 매핑.

## 2.5 디자인 철학 = 설계도(와이어링뷰) 중심 (사용자 확정)
> 이 툴의 본질 = **회로도 + 핀맵**. 표만이 아니라 **시각적 배선도(와이어링뷰)**가 핵심 뷰가 되어야 한다.
> (사용자가 ~30만원 주고 쓰던 회로도 툴의 역할을 자체완결로.) 이름 = **와이어링뷰(Wiring View)**.
- **와이어링뷰(ver0.2)** = 캔버스에 **아두이노 메가(핀헤더 D22~D53 + GND/5V 레일)** + **디바이스 노드**(버튼/스위치/센서/
  릴레이/LED 등 간단 심볼) + **배선**(디바이스↔핀 ID_NN, 디바이스↔GND = 핀+GND 방식 그대로). 보드/SEQ별 색상.
- 라벨: ID_NN · 시리얼ID(IN_NN) · 장치명. **블루프린트 감성**(다크 그리드·얇은 라인·모노스페이스·기술 도면).
- **핀맵 표 ↔ 와이어링뷰 양방향 동기화**(표 추가→노드 생성, 뷰 배선→데이터 반영). 노드 드래그·정렬.
- **배선도 SVG/PNG 내보내기**(현장 배선 참조) + HANDOFF 포함. 배전함 물리배치(§3-B)와는 별개(그건 ver0.3).

## 3. 회로도 — 두 뷰

### (A) 보드 핀맵 (논리) — SerialTunner 계승
- 보드별 핀(D22~D53=ID_01~32) ↔ 디바이스(이름/타입/모드) 매핑 표. 게이밍은 **시퀀스별 그룹**으로 묶어 표시.
- → PIMM_Registry(CSV) + 시리얼 프로토콜 문서 + (필요시) .ino 생성.

### (B) 배전함 물리배치 (실측) — 신설 핵심
- **배전함 기본 1m × 1.5m** 캔버스(실측 스케일).
- **부품 라이브러리**(실제 제원 크기): 앰프 2종, 멀티탭 6구, 방수형 SMPS 300W 2종, 단자대, 배선덕트 등 → 실 사이즈로 배치.
- **구획(존) 나눔 비주얼** + **가장 효율적인 배선 라인 구상**(전원·신호 분리, 단자대 경유, 배선덕트 경로).
- 결과 = 현장에서 이 도면대로 조인트하는 **배선 시공도**.

## 4. 워크플로우 (코워크 대화형)
```
사용자 ↔ 코워크 대화(장치·연출·배전 논의)
   → 코워크가 DeviceSeatAssistant에 도면/매핑을 그림(핸드오프 해석)
   → 팀이 툴에서 수정
   → 현장에서 도면대로 배선/조인트
```
- 게임에디터와 동일 패턴(설계→핸드오프→코워크). 산출: PIMM_Registry + 시리얼 프로토콜 + 배전 시공도 + (필요시).ino.

## 5. 게임에디터 연동
- 게이밍보드 버튼 = 게임에디터의 게임 인풋. **SEQ# 그룹 기준**으로 묶여 `combo_input_registry`(G1~G6)와 정합.
- 게임에디터 프로젝트(project.pimm.json)의 시퀀스/입력 → 게이밍보드 핀맵으로 가져오기(향후).

## 6. 기술 스택
- **자체완결 단일 HTML**(외부 의존성 0, 오프라인) — SerialTunner의 CDN React 의존 탈피, 게임에디터·허브와 동일 원칙. 다크 + #00FF99, 애플 톤 정합.

## 7. 단계 계획 (초안)
1. 개념/스펙 확정(본 문서) + 260502 표준·SerialTunner 정독.
2. 핀맵/프로토콜 코어(SerialTunner 자체완결 재구축) — 보드·핀·디바이스·시리얼·핸드오프.
3. 게이밍보드(시퀀스 그룹) + 게임에디터 연동.
4. 배전함 물리배치 도면(부품 라이브러리·실측·존·라인).
5. 코드 생성(Registry + 커스텀 .ino 보조) + QA.

## 8. 사용자 확정 사항 (반영)
- **표준은 기본값/참조, 불변 아님**: 최종 시리얼 규칙(**바이블**)은 **추후 사용자 인터뷰로 확정**. 그 뒤 **Pl로직·핌플레이어(.cs)를 이 툴 규격에 맞춰 수정**(툴이 규칙을 정의). → 지금은 260502를 **편집 가능한 기본값**으로, **골조+UI/UX 기능에 충실**.
- **인풋보드 vs 게이밍보드**: 인풋보드 = **시퀀스 진행 신호 수신 전용**(안정·소수). 게이밍보드 = **"인풋보드2"**(게임 버튼 다수 → 인풋보드가 감당 못 해 분화, 시퀀스 영향 적음, **빠르게 재매핑/피봇** 가능). 둘 다 입력형.
- **SerialTunner**: 아직 Pl로직·핌플레이어 정합은 **시기상조** → 지금은 자체완결 재구축(골조·UI/UX). 정합/바이블은 인터뷰 후.
- **배전함 부품 제원**: 매번 바뀔 수 있으므로 **그때마다 편집**(사용자 입력/수정). 고정 목록 X. + 향후 **장바구니 담아두면 코워크가 크롬제어로 분석·작업** → 툴은 **가이드만** 제공하면 됨.
- **배전 도면**: 실측 to-scale 2D 배치(ver0.2).

## 9. 허브 연동 & 위치
- 완성 시 **PIMMotion 허브에 등록** → 피모션 안의 두 번째 툴(게임에디터 다음).
- **피모션 섹터 분류**: 외부 툴 작업 보조 = **에디터**(예: 게임크리에이터=Unity), 자체 완결 작업 = **엔진**(예: 비주얼시나리오 HTML). *DeviceAssistant는 자체 HTML로 설계하되 산출은 물리 하드웨어/코워크로 — 분류는 추후 정리.* (엔진/에디터 세분화·나머지 런처는 추후.)
