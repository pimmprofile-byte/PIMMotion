# PIMM Launcher HUB — 전체 청사진 (북극성 · 현행 정본)

> 구 "피모션 허브" → **PIMM Launcher HUB** 로 리브랜딩. 팀 워크스페이스 런처(어도비 크리에이티브 클라우드 개념).
> **목표: 노션 대부분 기능 대체 + 코워크(클로드)가 상급자·동료가 되어 이 허브만으로 업무 온보딩·진행.**
> 원칙: **자체완결 단일 HTML(외부 의존 0, 오프라인) · 다크 미니멀 리퀴드글래스 + `#00FF99` · 데이터 주도 렌더.**
> 정본: GitHub `pimmprofile-byte/PIMMotion` (tools = `tool/`, docs = `docs/`). Drive는 미러/배포.
> 최종 업데이트: 2026-07-26 (이 세션 반영본). Drive 원본: `PIMMhub제작/_청사진_PIMMhub_Blueprint.md`.

## 1. 정체성 & 개념 매핑 (사용자 확정)
- **PIMM Launcher = 어도비 크리에이티브 클라우드** = 런처 그 자체. (유니티 단일에디터 비유 폐기.)
- 그 안에 **4개 동급 섹터** = **피모션 · 플로직 · 포피스 · 파트웍**. (CC의 앱들처럼 나란히.)
- **게임에디터·디바이스어시스턴트 등 개별 툴 = 피모션 안에** 위치(최상위 아님).
- 브랜딩: 워드마크 "PIMM Launcher + HUB 배지 + vN". PIMMotion(피모션)은 **섹터명**으로 유지(앱명과 구분).

## 2. 진입 구조 — Forge ↔ 커뮤니티 (상단 토글)
- **Forge** = 그린필드 4대 섹터 카드(바로 진입). PIMMotion·Partwork는 펼침(expandable).
- **커뮤니티** = 별개 에리어(비실무): 사내공지·바로가기 링크·비즈니스 서류. (구 "Track" 토글 → 커뮤니티로 전환.)
- **공정 파이프라인(Track)** 은 개념 중복 제거 위해 **파트웍 섹터 안으로 이동**.

## 3. 4대 Forge 섹터 (현행 상태)

### 3.1 플로직 Plogic — 학습/이론 (LIVE)
- 파일: `tool/PIMM_Plogic.ver0.2.html` (ver0.1 → 0.2). 마스터로직 교육 도구.
- 5모드: **이해하기 · 풀어보기 · 심화과정 · 아티잔 · 작업체계**.
- 콘텐츠: PPP→IMM 철학 / Tier·트랙(2트랙: PIMMersive[스케이프·엑스]·PIMMup[머셜·벤션]) / 파이프라인 **Beat→Note→Render→Work→Max** / 크래프트이론(8-Cell·Flow·어포던스 등) / **아티잔 인재체계**(6도메인·5계층 주니어~마스터·4도달지점 아티잔→제너럴리스트→디렉터→마스터[EP]·리더십).
- **Day 마스코트**: 스프라이트 정본 = Drive `[4.아카이브].Arc/데이캐릭터/` (DAY_charC 정면·charL/charR 걷기). ver0.2에서 **SVG 임베드 + charL↔charR 걷기 애니메이션**(reduced-motion 시 charC 고정).
- 심화 나머지 5이론(공간구성·게임퍼즐·장면연출·장르컨셉·운영설계) = 🔒 원문 정독 후.

### 3.2 포피스 Poffice — 업무보고/운영 (LIVE)
- 파일: `tool/PIMM_Poffice.ver0.12.html` (0.7 .js 로드 → 0.8 샘플경고·raw_omitted·version가드 → 0.9 **사내공지 notices 렌더** + **연동상태 칩=generated_at 기준·신호등·툴팁** → 0.10 **Day 달리기 애니메이션**(바운스) → 0.11 **Day 좌우반전 + 마일스톤 배지/툴팁** → 0.12 **마일스톤 팝업 트랙중앙 고정(안 잘림) + 체크리스트 상태 범례 + 옐로게이트 인물별 정책배지 + 결재 인박스**(레드→대표 심상윤, report 인물 옐로→결재자 오세원·유지호 자동 취합·색인)). **읽기전용 대시보드 + 체크·메모만 로컬**.
- 흐름(5단계): `poffice-skill`(기록) → `poffice-motherlog`(집계→`poffice_board.json`) → 대시보드(시각화) → export(체크·메모) → 반영 → `poffice-report-bot`(페르소나 브리핑).
- 3판: 미션보드(Day char 마일스톤) · 게이트보드(🔴🟡🟢 권한 신호등) · 투두. + 인물선택(본인만) · WO배너 · 게이미피케이션.
- **★원문 보존 정책(2026-07-26)**: 마더로그 요약 폐기 → `sessions[].raw` 원문 전문 + 1줄 summary, **분단위 타임스탬프** 필수.
- **사내공지 `notices[]`**: durable 소스 `06_Notice_사내공지/` → 매 run 집계. 트리거 "사내공지로 해줘"/"공지 내려줘". 대시보드 강조 렌더.
- **연동상태(v0.5 반영)**: 상단바에 최신 세션로그 ts + 상대시간 + 신선도 점(초록<24h/노랑<72h/빨강) 상시 표시, 클릭 시 `poffice_board.json` 재로드. title에 generated_at. (§I 나머지 원문뷰·notices는 차기.)
- 스킬 3종 = 플러그인 **v0.9.2** 반영. 스펙 정본: `docs/poffice-board-spec.md`(A~H + §I 확장).
- 남은 것: 대시보드 build에 §I 요구(원문뷰·신선도·notices·새로고침) 반영 + 실 `poffice_board.json` 첫 생성(motherlog) + 자동예약(CronCreate) + Day 스프라이트 연결.

### 3.3 피모션 PIMMotion — 소프트워크 파트너 (LIVE · 가장 많은 툴)
**두 축으로 구분** (허브 피모션 카드 펼침):

**A. 에디터 · 외부 전문툴 + 코워크**
| 툴 | 파일 | 상태 |

**B. HTML 빌드엔진 · 자체완결 외부송부자료** (신설 · 전부 🚧)
- **1.제안서 2.기획안 3.비주얼시나리오 4.견적서 5.계약서**
- 성격: **외부 송부자료를 만드는 엔진.** "엔진"인 이유 = **규격화된 폼을 기본**으로 하기 때문. 단, 테마·프로젝트·상황별로 달라져 **코워크 인터뷰(최소 입력 기반)로 빌드**.
- 이후: **에셋관리(이미지·음향 등) 보조 툴** 추가 목적.
- 세부 기능은 **툴 하나 만들 때마다 개별 빌드**. (현재는 골조 + 공사중.)
- ※ 재료 있음: Drive `pimm-proposal-maker` 플러그인 + 실 제안서 HTML(PIMM_Crk/Gws_proposal) → 제안서부터 착수 유력.

### 3.4 파트웍 Partwork — 하드워크 파트너 (구조만 🚧)

## 5. 배포
- **현재**: Drive `PIMM_Launcher` 폴더에 허브 + 5개 툴 HTML **co-location**(상대경로 `./` 링크 → 카드 클릭 실행). 더블클릭 실행.
- **포피스 데이터 로드**: 마더로그가 런처 폴더에 `poffice_board.json` + `poffice_board.js`(=`window.POFFICE_BOARD=…`) 미러. 대시보드 v0.7이 `.js`(script 태그)를 우선 로드 → **더블클릭(file://)에서도 자동**. (fetch(.json)은 file://서 차단되므로 .js가 핵심.) 코워크 핸드오프 = `docs/handoff-poffice-js-mirror.md`.
- **후속**: **Electron 데스크톱앱**(repo `desktop/`) — 허브 진입, NSIS/.dmg 듀얼빌드. 2.0 마스터링 때 로고·아이콘 확정.
- ⚠️ 큰 HTML(허브 339KB·게임 611KB)은 코워크가 Drive에 직접 업로드 불가(도구 한계) → 사용자가 GitHub raw 다운로드 후 폴더에 배치.
