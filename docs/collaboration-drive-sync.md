# 팀 공유 모델 — 구글드라이브를 서버 삼아 (서버·MCP·API 없이)

> **결정(사용자)**: 별도 백엔드/MCP/API 불필요. **구글드라이브의 클라우드 동기 = 서버 역할.**
> 프로젝트 폴더(project-folder-spec.md)를 **드라이브 데스크톱 동기폴더 안**에 두면, 드라이브가
> 자동 동기 → **팀원끼리 공유(깃 비슷)**. 데스크톱 앱(2.0)이 이 로컬 동기폴더를 네이티브로 다룬다.

---

## 1. 구조 (서버 없음)

```
[구글드라이브 클라우드]  ← "서버"
        ▲ 자동 동기 ▼
[팀원 A PC] Drive동기폴더/PIMM_Projects/<프로젝트>/   ← 데스크톱 앱으로 열어 편집
[팀원 B PC] Drive동기폴더/PIMM_Projects/<프로젝트>/   ← 같은 폴더가 동기되어 보임
```

- 편집 = 로컬 폴더의 `project.pimm.json`·`assets/*`에 저장 → 드라이브가 클라우드로 올림 → 팀원에게 내려감.
- **MCP/API/서버 인증 전부 불필요.** 온라인 구동 = 드라이브 동기가 대신.
- 인코딩 산출(`encode/`)도 같은 폴더 → 코워크가 드라이브 폴더에서 읽어 유니티 빌드(distribution-and-build.md와 정합).

## 2. "깃 같은 것" — 되는 것 / 안 되는 것 (정직하게)

| | 드라이브 동기 | 비고 |
|---|---|---|
| 팀 공유·배포 | ✅ 자동 | zip·git 명령 0 |
| 버전 롤백 | ✅ 드라이브 버전기록 | 파일별 이전 버전 복원 |
| **동시 편집 병합(머지)** | ❌ 없음 | 두 명이 **같은 파일** 동시 편집 → **"(충돌된 사본)"** 생성(덮어쓰기/분기 아님) |
| 브랜치·PR·커밋 히스토리 | ❌ | 깃과 다름 |

→ **공유는 완벽, 동시-같은파일 편집만 주의.**

## 3. 충돌 최소화 장치 (가벼운 깃처럼)

1. **파일 분리(ver1.8)**: config를 씬/시퀀스 단위로 쪼갬 → 각자 다른 씬 작업 시 같은 파일 안 건드림 → 충돌 거의 0.
   (`scenes/<SEQ>_<scene>.json` + 얇은 `project.pimm.json` 인덱스)
2. **소프트 잠금**: `.pimm/lock.json`에 `{editor, openedAt}` 기록 → 다른 팀원이 그 프로젝트/씬 열 때 "○○님 편집 중" 경고(강제 아님, 관례).
3. **버전 스냅샷**: 마일스톤마다 `encode/`로 내보내기 = 안정본 보존. 드라이브 버전기록과 병행.
4. **원본/작업본 분리**(권장 관례): 공유 원본은 읽기 위주, 실제 편집은 담당자 지정.

## 4. 데스크톱 앱 = 2.0 (Tauri)

- 지금 HTML의 프로젝트 폴더 기능은 **File System Access API(크롬 전용)** → 데스크톱 앱으로 감싸면
  **네이티브 파일시스템**이 되어 OS/브라우저 제약 없이 드라이브 폴더를 안정적으로 읽고 씀.
- Tauri = 작은 바이너리, 기존 HTML 거의 그대로 로드(로직 재작성 최소). 앱 아이콘·`.pimm` 파일연결·자동업데이트.
- **타이밍**: 2.0에서. 2.0 = 마스터링(로고·실행가이드) + 데스크톱 앱화 묶음(기능 프리즈 후 감싸기).
- 순수 감싸기 1~2일, 팀 배포수준(서명·설치파일·자동업뎃) ~1주.

## 5. 정리

- **서버/API/MCP 없음.** 드라이브 동기 = 공유 인프라. 팀은 폴더를 열고 편집만.
- 깃의 "공유·롤백"은 얻고, "머지"는 파일분리+소프트잠금으로 우회.
- **2.0 = 데스크톱 앱 + 드라이브 폴더 + 마스터링.**
