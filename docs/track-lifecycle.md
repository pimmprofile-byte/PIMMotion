# Track — 아이디어 5공정 기반 프로젝트 생애주기

> **Track**은 하나의 프로젝트를 **테마의 최초 공정부터 끝까지** 끌고 가는 진입/운영 개념이다.
> Forge(빠른 에디터 진입)와 병렬. Track의 뼈대는 **Plogic의 아이디어 5공정**이며,
> 실제 트랙별 구현·변형은 **Partwork** 소관이다(현재 빈약 → 채워지면 Track이 살아남).
> 출처: Plogic `00.4_아이디어 공정.md`.

---

## 1. 아이디어 5공정 (Beat → Note → Render → Work → Max)

핌아트웍스의 기획 공정 = **형태 없는 영감을 물리적 실체로 안정화**하는 과정.

| 공정 | 정의 | 핵심 산출/도구 |
|---|---|---|
| **Beat (비트)** | 원초적 영감의 파편 (아직 검열 전) | 비트제안서 + 버추얼 스토리보드. **Tier(T1~T3)로 깊이 결정** |
| **Note (노트)** | 논리의 골조 = 상세 스크립트 | 시퀀스·스텝·공간구조. 기술적 헌법 필터 작동 |
| **Render (렌더)** | **설계 단계** — 서류작업을 통한 기획·설계 | **도구 사용 기반(어도비·스케치업·유니티 등)**, 도면 이원화(기획/시공), 표준 스펙시트, 설계 문서 |
| **Work (워크)** | 완성된 몰입의 실체 | 현장 시공, **90% 시점 QA 테스터**, 최종 밸런싱 |
| **Max (맥스)** | 사후 가치극대화 (post-delivery) | 아카이빙·IP·마케팅·스케치필름·재계약. *공기(工期)·관계가 Max를 좌우* |

> **게임 에디터 에이전트는 Render 공정에서 쓰는 설계 도구 중 하나다** (어도비·스케치업·유니티 등과 나란히).
> Render는 도구 기반 기획·설계 작업이므로, 각 에디터 에이전트가 이 단계의 손발이 된다.
> (※ 과거 문서는 Render를 "쯔꾸르(RPG Maker)/아두이노 물리구현"으로 기술하나, **알만툴은 현재 미사용** —
> Render는 물리구현이 아니라 **설계 단계**로 본다.)

### Tier & Track 축
- **Tier(밸류)**: T1 프리미엄비트(60~70p) / T2 테마비트·스페이스비트(10~25p) / T3 베이직비트(5~10p, 단가 500만↓).
- **Track(사업 파트)**: 아래 §2. (분류 순서: ① Tier → ② Part → ③ Track 확정)
- **Plogic ↔ Partwork**: Plogic = '왜/무엇'(원리·판단), Partwork = '어떻게/얼마'(트랙별 구현·장치·비용).

## 2. Track 카테고리 (사업 파트)

| 트랙 | 대상 | Max 초점 |
|---|---|---|
| **핌업 (PIMM-UP)** | 팝업 콘텐츠 제작 | 짧게 끝남 → 고객반응 수확 + 클라이언트 관계 |
| **피머시브 (PIMMersive)** | 상설 이머시브 매장 제작 | 오래 둠 → 매장 안정화·운영 최적화 |
| **기타** | 머더미스터리, 프리프로젝트 준비 등 | 케이스별 |

각 트랙은 5공정(Beat~Max)을 밟되, 트랙별 공정 변형·장치 화이트리스트·실측/시공 실값은 **Partwork**에서 관리.

## 3. Track 가동 생애주기 (핌코프 + 스킬크리에이터)

Track을 켜면 하나의 **프로젝트**가 시작되고, **핌코프(우리가 만든 Claude 코워크 플러그인)** 와 함께 굴러간다.

```
[Track 가동]
   └▶ 스킬크리에이터 스킬로 그 프로젝트(트랙) 전용 **프로젝트 에이전트** 생성·활성화
        └▶ 진행 중:
             · 세션로그 자동 기록 (퍼플필드/로그)
             · 프로젝트 진행상황 추적 (5공정 어디까지)
             · 위클리 알림 (주간 리포트/리마인드)
        └▶ 프로젝트 드랍/마감 시:
             · 트랙 종료 → 프로젝트 에이전트 스킬 제거
             · 아카이빙 (블루필드/아카이브 = 완결 케이스 라이브러리 원료)
```

- **핌코프** = Claude 코워크 플러그인. Track은 이 플러그인과 함께 진행(워크플로우 이해 필요).
- **스킬크리에이터** = 프로젝트 에이전트를 스킬로 만들어 붙였다 떼는 장치(가동 시 생성, 마감 시 제거).
- **산출/로그 위치**: 세션로그·리포트 → 퍼플필드(로그), 아웃풋 → 옐로필드(아웃풋 섹터), 완결 아카이브 → 블루필드.

> ⚠️ 현재 상태: 이 생애주기(플러그인 연동·스킬 자동생성/제거·위클리 알림·자동 아카이빙)는 **미구현(🚧)**.
> 우선 허브의 Track에 **5공정·카테고리·생애주기 구조**를 정확히 세워두고, 실제 연동은 단계적으로.

---

## 4. 로드맵 (하나씩)

1. ✅ 5공정 학습(본 문서) + 허브 Track 구조화(5공정·카테고리·생애주기 🚧 표기).
2. 🚧 Partwork 채우기 → 트랙별 공정 변형이 Track에 반영(진짜 파이프라인 가동).
3. 🚧 핌코프 플러그인 ↔ Track 연동 워크플로우 정의.
4. 🚧 스킬크리에이터로 프로젝트 에이전트 자동 생성/제거 + 세션로그·위클리·아카이빙.

> Track은 범위가 넓다. Plogic(원리)은 있으므로, **Partwork(구현)와 핌코프 연동**이 채워지는 순서로 Track이 실체화된다.
