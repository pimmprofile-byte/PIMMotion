# PIMM UnityGameCreator — 툴 개념 (북극성)

> 이 툴이 무엇인지 한 장으로. 모든 개발 패스(PART 6~9)와 QA는 이 그림에 맞춘다.
> **정의(사용자)**: 세 개의 익숙한 툴의 강점을 합치고, 그 결과를 **바이브코딩으로 코워크와
> 소통하는 핸드오프 + 에셋 아카이빙 폴더**로 내보내는 게임 에디터.

---

## 1. 세 패러다임의 결합

| 영역 | 레퍼런스 툴 | 이 툴에서의 역할 |
|---|---|---|
| **게임뷰 레이아웃** (에셋의 공간 배치) | **Adobe Illustrator** | 이미지/에셋을 1920×1080에 배치·**정렬**·레이어. 정렬/분배(Align/Distribute) 필수 |
| **인터랙션 순서** (시퀀스·씬 내부 흐름) | **Premiere Pro (타임라인)** | 시퀀스>씬>요소를 트랙으로. **단, 가로축은 시간이 아니라 "플레이 중 인터랙션 순서"** |
| **상세 연출·게임 기능** | **Unity 인스펙터 + 하이어라키** | 인스펙터=속성/기능/상태/전환 메모, 하이어라키=레이어 높낮이(z-order) |
| **최종 산출** | — | **핸드오프(인코딩) + 에셋 아카이빙 폴더** → 코워크가 바이브코딩으로 빌드 |

즉 **공간=일러스트, 흐름=프리미어, 연출/기능=유니티, 산출=핸드오프+에셋아카이브.**

---

## 2. 핵심 교정 — 타임라인은 "인터랙션 기준"이다

프리미어의 타임라인은 시간축이지만, **게임은 시간이 아니라 플레이어의 인터랙션으로 진행**한다.
그래서 이 툴의 타임라인 가로축은 **인터랙션 순서**다.

```
트랙(레이어) │ 인터랙션1        인터랙션2         인터랙션3        (엔드마크)
─────────────┼──────────────────────────────────────────────────────────
 배경        │ [██████ 배경A 유지 ████████████████][ 배경B ]
 UI/버튼     │ [ PressAnyKey ]→(전환)[ 로딩 ]→[ 사용설명 ]→
 텍스트      │ [ "PRESS ANY KEY" ]          [ "LOADING" ]
 오디오(BGM) │ [████████ BGM 유지(끊김없음) ████████████]
 SFX         │        ♪(인터랙션1 시)     ♪            ♪
```

- **인터랙션 마커**: 가로축의 각 지점 = 인터랙션1, 2, 3…(입력 발생 시점). 각 마커에 **노트/액션**을
  붙일 수 있다 — "인터랙션1 하면 → 디졸브로 다음 씬 / 상태2로 전환 / SFX 재생 / 시퀀스 종료" 등.
- **클립 = 요소의 지속 구간**: 요소가 유지되는 인터랙션 범위를 막대로 표현(= 씬 간 연속성).
  유지=긴 막대(같은 오브젝트 재사용, 깜빡임/재시작 없음), 변경=막대 교체, 등장/퇴장=막대 시작/끝.
- **트랜지션 = 클립 경계**: 컷/페이드/디졸브를 인터랙션 경계에 부착 + 메모.
- **엔드마크**: 시퀀스의 마지막 인터랙션 = 시퀀스 종료 → 다음 시퀀스.
- **플레이헤드**: 특정 인터랙션 지점 선택 → 프로그램 모니터(캔버스)가 그 순간의 화면 구성을 보여줌.

> 정리: **프리미어의 트랙/클립/트랜지션 UI는 그대로, "시간"만 "인터랙션 순서"로 치환.**

---

## 3. 게임뷰 = 일러스트레이터 (공간 편집)

- 캔버스(프로그램 모니터)에서 이미지박스/프리팹/텍스트를 **드래그·리사이즈·정렬**.
- **정렬/분배(사용자 명시)**: 좌/중앙/우, 상/중/하 정렬, 수평·수직 분배, 크기 맞춤, 캔버스/선택 기준.
  다중 선택 후 일러스트처럼 한 번에. (PART 7)
- 레이어 높낮이(z-order)는 하이어라키에서.

---

## 4. 상세 연출·기능 = 유니티 인스펙터/하이어라키

- 인스펙터: 속성(Transform/opacity) + **논코딩 메모**(상호작용·기능·프롬프트) + 상태(배리에이션) + 전환.
- 하이어라키: 레이어 트리, 락/가시성, z-order.

---

## 5. 최종 산출 = 핸드오프 + 에셋 아카이빙 폴더

이 툴의 **결과물**은 두 가지이고, 이걸로 코워크가 바이브코딩으로 빌드한다.

1. **핸드오프(인코딩)**: 씬·인터랙션 흐름·연속성·상태·전환·좌표(unity 앵커)·오디오·프리팹을
   기계 파싱 가능한 데이터로. (PART 9, `encoding-and-build.md`)
2. **에셋 아카이빙 폴더**: 프로젝트/시퀀스/씬 단위로 정리된 에셋(이미지/오디오) 폴더.
   교체·재사용·버전관리가 쉽도록 구조화(SVG 박스별 인덱스와 연결). Drive `PIMMplayer_JSON` 하위.

→ **{핸드오프 + 에셋아카이브} + Unity + 핌플레이어 프로젝트** = 코워크/팀원이 게임을 빌드.

---

## 6. 왜 이 조합인가 (전략)

- 팀원 전원이 **프리미어·일러스트·파포**에 익숙 → 학습비용 최소(유니티는 개발친화적이라 진입장벽).
- **게임제작·장치설계/코딩·영상제작**을 같은 작업방식(타임라인+레이아웃+인스펙터)으로 통일.
- 이 타임라인 패러다임은 **향후 영상제작 가이드툴**에 그대로 재사용 가능.
- 사용성 테스트 페르소나: **전문툴 무경험, 파워포인트 정도만 만져본 사람** 기준.

## 7. 사용성 제1원칙 — 점진적 복잡도 (Progressive Disclosure)

> 여러 기능을 쌓으며 복잡도가 누적됐다. 이제 **추가보다 단순화**가 우선. 초심자가 첫 화면에서
> 막히면 안 된다. 앞 트랙일수록 직관적·직접 작업, 뒤 트랙일수록 정보 위주·자동 정리.

**트랙 램프 (쉬움 → 정보):**
- **앞단 (직접 작업 — 초심자가 여기서 대부분 완성):**
  1. 🎨 레이아웃 — 이미지/텍스트/프리팹 배치·정렬 (가장 쉬움)
  2. ⚙️ 기능(인스펙터) — 박스에 기능/상호작용·인터랙션 흐름
  3. 🔊 소리·전환 — SFX/BGM, 씬 전환
- **뒷단 (정보·자동/검토 — 안 건드려도 됨):**
  4. 📋 비트시트 — 앞단 내용 자동 정리(읽기 위주, Cowork 확인)
  5. 🧩 에셋·config·인코딩 — 매트릭스/config/리스킨/인코딩(정보 밀도 ↑)
  6. 🔧 시뮬레이트·빌드 — 검수 정보

**규칙:**
- 첫 화면 = 레이아웃, 필요한 것만 노출. 어려운 뒷단(config 9종·integrate·simulate)은 **"고급/핸드오프" 그룹으로 접어둔다.**
- 각 단계는 그 단계에서 필요한 것만 보이고, 고급 옵션은 감춘다(펼치면 나옴).
- "이미 내가 직접 만든 것"이 뒷단에 자동으로 쌓여 보이게 → 정보량이 늘어도 이해된 상태.
