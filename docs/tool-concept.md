# PIMM UnityGameCreator — 툴 개념 (북극성)

> 이 툴이 무엇인지 한 장으로. 모든 개발 패스(PART 6~9)와 QA는 이 그림에 맞춘다.
> **정의(사용자)**: 세 개의 익숙한 툴의 강점을 합치고, 그 결과를 **바이브코딩으로 코워크와
> 소통하는 핸드오프 + 에셋 아카이빙 폴더**로 내보내는 게임 에디터.

---

## 1. 세 패러다임의 결합

| 영역 | 레퍼런스 툴 | 이 툴에서의 역할 |
|---|---|---|
| **게임뷰 레이아웃** (에셋의 공간 배치) | **Adobe Illustrator** | 이미지/에셋을 1920×1080에 배치·**정렬**·레이어. 정렬/분배(Align/Distribute) 필수 |
| **인터랙션 순서** (시퀀스·씬 내부 흐름) | **Premiere Pro (타임라인)** | 시퀀스>씬>요소를 트랙으로. **단, 가로축은 시간이 아니라 "플레이 중 인터랙션 순서"** |
| **상세 연출·게임 기능** | **Unity 인스펙터 + 하이어라키** | 인스펙터=속성/기능/상태/전환 메모, 하이어라키=레이어 높낮이(z-order) |
| **최종 산출** | — | **핸드오프(인코딩) + 에셋 아카이빙 폴더** → 코워크가 바이브코딩으로 빌드 |

즉 **공간=일러스트, 흐름=프리미어, 연출/기능=유니티, 산출=핸드오프+에셋아카이브.**

## 2. 핵심 교정 — 타임라인은 "인터랙션 기준"이다

프리미어의 타임라인은 시간축이지만, **게임은 시간이 아니라 플레이어의 인터랙션으로 진행**한다.
그래서 이 툴의 타임라인 가로축은 **인터랙션 순서**다.

```
트랙(레이어) │ 인터랙션1        인터랙션2         인터랙션3        (엔드마크)
─────────────┼──────────────────────────────────────────────────────────
 배경        │ [██████ 배경A 유지 ████████████████][ 배경B ]
 UI/버튼     │ [ PressAnyKey ]→(전환)[ 로딩 ]→[ 사용설명 ]→
 텍스트      │ [ "PRESS ANY KEY" ]          [ "LOADING" ]
 오디오(BGM) │ [████████ BGM 유지(끊김없음) ████████████]
 SFX         │        ♪(인터랙션1 시)     ♪            ♪
```

- **인터랙션 마커**: 가로축의 각 지점 = 인터랙션1, 2, 3…(입력 발생 시점). 각 마커에 **노트/액션**을
  붙일 수 있다 — "인터랙션1 하면 → 디졸브로 다음 씬 / 상태2로 전환 / SFX 재생 / 시퀀스 종료" 등.
- **클립 = 요소의 지속 구간**: 요소가 유지되는 인터랙션 범위를 막대로 표현(= 씬 간 연속성).
  유지=긴 막대(같은 오브젝트 재사용, 깜빡임/재시작 없음), 변경=막대 교체, 등장/퇴장=막대 시작/끝.
- **트랜지션 = 클립 경계**: 컷/페이드/디졸브를 인터랙션 경계에 부착 + 메모.
- **엔드마크**: 시퀀스의 마지막 인터랙션 = 시퀀스 종료 → 다음 시퀀스.
- **플레이헤드**: 특정 인터랙션 지점 선택 → 프로그램 모니터(캔버스)가 그 순간의 화면 구성을 보여줌.

> 정리: **프리미어의 트랙/클립/트랜지션 UI는 그대로, "시간"만 "인터랙션 순서"로 치환.**

## 3. 게임뷰 = 일러스트레이터 (공간 편집)

- 캔버스(프로그램 모니터)에서 이미지박스/프리팹/텍스트를 **드래그·리사이즈·정렬**.
- **정렬/분배(사용자 명시)**: 좌/중앙/우, 상/중/하 정렬, 수평·수직 분배, 크기 맞춤, 캔버스/선택 기준.
  다중 선택 후 일러스트처럼 한 번에. (PART 7)
- 레이어 높낮이(z-order)는 하이어라키에서.

### 3.1 파워포인트식 스마트 가이드 (정밀 배치, ver1.6) — 사용자 핵심 요청
> 파워포인트처럼 **드래그하는 순간 다른 개체·캔버스 기준으로 간격/정렬을 동적으로 맞춰주는** 스마트 가이드.
- **정렬 가이드(동적)**: 드래그 중 다른 박스의 **좌/우/상/하/중심선** 또는 **캔버스 중심·모서리**와 맞으면
  점선 가이드가 나타나고 그 선에 **스냅**.
- **균등 간격 가이드(핵심)**: 여러 박스가 있을 때 **박스 사이 간격이 같아지는 위치**에서 **이중 화살표(간격 인디케이터)**가
  뜨고 스냅 → "위아래(또는 좌우) 여백이 자동으로 균등"해짐. (파워포인트의 equal-spacing 마커)
- **여백 스냅**: 캔버스 상하/좌우 **여백이 같아지거나** 중앙에 오면 스냅.
- **Alt 드래그 = 스냅 일시 해제**(미세조정). 스냅 임계값 ~8px. 리사이즈에도 적용.
- (보조) 고정 그리드 오버레이도 토글로 제공하되, **주 기능은 개체 기준 스마트 가이드**.

### 3.2 원클릭 균등 배치 헬퍼 (ver1.6)
- 다중 선택 후 **"가운데 가로 균등" / "가운데 세로 균등"** 한 번 = 선택 박스들을 **캔버스 중앙에 한 줄, 간격 균등, 교차축 중앙정렬**로 배치.
- 예: 박스 3개 선택 → "가운데 가로 균등" → 화면 중앙에 3개가 균등 간격으로 가로 정렬. (일러스트 정렬/분배는 세밀조정용으로 유지)

### 3.4 에셋 제작 방식 — 크롭프레임 / 풀프레임 (ver1.7)
> 이미지 에셋을 만드는 두 방식. **에셋마다·씬마다 다를 수 있음** → **각 박스(특히 이미지에셋) 속성창에
> "프레임유형" 토글**로 둔다(박스 단위 속성). 유니티 임포트·클립·좌표 해석이 달라지므로 스키마에 `frameType` 표기.
- **크롭프레임 (Crop-frame)**: 이미지 파일 크기 = **픽셀 박스 크기**로 잘라 제작. 좌표(앵커)로 배치. 개별 오브젝트, 재배치·재사용·리스킨 유리, 파일 작음.
  - Unity: 박스 W×H 스프라이트를 `unity.anchorMin/Max` 위치에 배치.
- **풀프레임 (Full-frame)**: 이미지 = **1920×1080 전체 화면**, 콘텐츠가 좌표 위치에 이미 포함되어 제작. 합성 정확(WYSIWYG), 파일 큼, 위치 고정.
  - Unity: 풀스크린 RectTransform(전체 앵커)로 배치, 위치는 이미지에 구워짐. 박스 좌표는 "콘텐츠 영역 표시"용.
- **UI**: 박스 인스펙터에 **프레임유형 토글 버튼(크롭프레임 ↔ 풀프레임)**. 이미지/가변이미지 박스에 노출.
- 클립과 상호작용: 크롭프레임=박스에 클립, 풀프레임=프레임(1920×1080) 기준 클립.
- 스키마: box에 `frameType:"cropframe|fullframe"` **추가만**(기본 cropframe, 하위호환). 인코딩 번들·SVG 아트보드에도 반영.

### 3.3 클리핑마스크 (ver1.7) — "일러스트 대체"의 마지막 조각
> 팀이 일러스트를 쓰는 이유 = **① 정밀 좌표 ② 클리핑마스크**. ①은 좌표+스마트가이드(§3.1)로 커버.
> **②를 이 툴에 넣으면 일러스트 없이 레이아웃이 자체완결**된다.
- **도형 클립**: 박스에 사각형/둥근사각형/타원 마스크 → 이미지가 그 모양으로 잘림. (`clip-path`)
- **마스크 박스 클립**(일러스트식): 마스크 박스(위) + 콘텐츠 박스(아래) 선택 → "클리핑마스크 만들기" →
  콘텐츠가 마스크 박스의 모양/영역으로 잘림. 해제 가능.
- **브라우저 표현**: CSS `clip-path` / SVG `<clipPath>`(캔버스 미리보기 정확).
- **config/Unity 매핑**: `clip:{ type:"rect|roundrect|ellipse|maskBox", maskBoxId?, radius?, geometry }` →
  코워크가 유니티에서 **사각/둥근=RectMask2D, 타원/커스텀=SpriteMask(알파)** 로 결정론적 재현.
- 인코딩 번들 box 스키마에 `clip` 필드 **추가만**(하위호환). SVG 아트보드에도 클립 반영.

#### 3.3.1 클리핑박스 = 전용 박스 타입 (ver1.8 다음) — 사용자 결정
> ver1.7 클립은 "박스 2개 선택 → 클리핑마스크 만들기"라 번거로움. 사용자 결정:
> **클리핑박스를 하나의 박스 타입**으로 만들어(이미지·텍스트·가변이미지·배경처럼) **직접 생성**하고,
> 그 아래 콘텐츠를 그 영역/모양으로 자른다. (크롭 핸들 도구 대신 이 방식 채택 — 클리핑마스크 은유 유지.)
- **생성 메뉴에 "클리핑박스" 추가**: 우클릭/빈영역 생성 · 박스 ▸ …에 클리핑박스 항목. 도형 선택(사각/둥근/타원).
- 배치하면 **그 영역/모양으로 아래(또는 지정된) 콘텐츠 박스가 잘림**. 클리핑박스 이동/리사이즈 → 클립 실시간 갱신.
  기존 `maskFor`/`clip:{type:maskBox}` 메커니즘 재사용하되, **박스를 새로 만들기만 하면 되도록** UX 단순화.
- 렌더: 클리핑박스는 경계(점선)만, 콘텐츠는 잘린 결과. 인코딩·SVG·Unity 매핑(RectMask2D/SpriteMask)은 ver1.7과 동일.
- 스키마: 클리핑박스 = `role:"clip"`(또는 `maskFor`) 표식 + 도형. **추가만**(하위호환).

#### 3.3.2 자르기(크롭) 도구 (ver1.8 다음) — 클리핑박스와 함께 제공
> 사용자: 클리핑박스 **더불어 자르기 도구도** 원함(용도 구분 — 클리핑박스=마스크 요소, 크롭=이미지 자체 트림).
- 이미지 박스 선택 → **"✂️ 자르기"** → 크롭 모드: 원본 전체 반투명 + **크롭 핸들(8방향)** 드래그로 보일 영역 지정
  + 이미지 내부 팬 → 적용 시 그 영역만. **비파괴적**(원본 유지, `crop:{x,y,w,h}` 값만 저장 → 재조정 가능).
- Unity: 스프라이트 rect/uv 또는 RectMask2D로 **동일 영역** 재현. 인코딩·SVG 반영.

#### 3.3.3 WYSIWYG 보장 — "보는 것 = 빌드 결과" (사용자 확인)
> **원칙**: 레이아웃뷰에서 보는 구도가 유니티에서 그대로 나온다. **비파괴 크롭도 결과는 그대로 유지**되고
> 값이 인코딩에 실려 결정론적으로 재현된다.
- **완전 동일(픽셀)**: 좌표(unity 앵커)·z순서·클립·크롭·프레임유형·투명도 — 전부 config 데이터 → 임포터가 동일 재현.
- **유일한 차이(정직)**: 텍스트박스 **폰트 렌더링**(자간/힌팅)은 브라우저↔Unity TextMesh 미세차. 위치·크기는 맞음.
  → 최종 텍스트는 유니티 Play로 확인(워크플로우 ④). 이미지/레이아웃/크롭/클립은 WYSIWYG.

## 4. 상세 연출·기능 = 유니티 인스펙터/하이어라키

- 인스펙터: 속성(Transform/opacity) + **논코딩 메모**(상호작용·기능·프롬프트) + 상태(배리에이션) + 전환.
- 하이어라키: 레이어 트리, 락/가시성, z-order.

## 5. 최종 산출 = 핸드오프 + 에셋 아카이빙 폴더

이 툴의 **결과물**은 두 가지이고, 이걸로 코워크가 바이브코딩으로 빌드한다.

1. **핸드오프(인코딩)**: 씬·인터랙션 흐름·연속성·상태·전환·좌표(unity 앵커)·오디오·프리팹을
   기계 파싱 가능한 데이터로. (PART 9, `encoding-and-build.md`)
2. **에셋 아카이빙 폴더**: 프로젝트/시퀀스/씬 단위로 정리된 에셋(이미지/오디오) 폴더.
   교체·재사용·버전관리가 쉽도록 구조화(SVG 박스별 인덱스와 연결). Drive `PIMMplayer_JSON` 하위.

→ **{핸드오프 + 에셋아카이브} + Unity + 핌플레이어 프로젝트** = 코워크/팀원이 게임을 빌드.

---

## 6. 왜 이 조합인가 (전략)

- 팀원 전원이 **프리미어·일러스트·파포**에 익숙 → 학습비용 최소(유니티는 개발친화적이라 진입장벽).
- **게임제작·장치설계/코딩·영상제작**을 같은 작업방식(타임라인+레이아웃+인스펙터)으로 통일.
- 이 타임라인 패러다임은 **향후 영상제작 가이드툴**에 그대로 재사용 가능.
- 사용성 테스트 페르소나: **전문툴 무경험, 파워포인트 정도만 만져본 사람** 기준.

## 7. 사용성 제1원칙 — 점진적 복잡도 (Progressive Disclosure)

> 여러 기능을 쌓으며 복잡도가 누적됐다. 이제 **추가보다 단순화**가 우선. 초심자가 첫 화면에서
> 막히면 안 된다. 앞 트랙일수록 직관적·직접 작업, 뒤 트랙일수록 정보 위주·자동 정리.

**트랙 램프 (쉬움 → 정보):**
- **앞단 (직접 작업 — 초심자가 여기서 대부분 완성):**
  1. 🎨 레이아웃 — 이미지/텍스트/프리팹 배치·정렬 (가장 쉬움)
  2. ⚙️ 기능(인스펙터) — 박스에 기능/상호작용·인터랙션 흐름
  3. 🔊 소리·전환 — SFX/BGM, 씬 전환
