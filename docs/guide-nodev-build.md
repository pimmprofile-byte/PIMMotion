# PIMM UnityGameCreator — 무개발 사용자 가이드 (ver1.0)

> **목표**: 개발 지식이 전혀 없어도, 게임을 명확히 구상하고 그래픽 에셋만 준비하면
> 이 툴 하나로 게임을 **인코딩**하고 → 핌플레이어(Unity)로 **직접 빌드·수정**할 수 있다.
> 대상: 코딩을 모르는 기획자/디자이너 (파워포인트 정도만 써본 사람 기준).

---

## 0. 이 툴은 세 개의 익숙한 툴을 합친 것

| 하는 일 | 닮은 툴 |
|---|---|
| 화면에 이미지 **배치·정렬** (게임뷰 = 프로그램 모니터) | **일러스트레이터** |
| 게임 **진행 순서**(씬·인터랙션)를 트랙으로 (하단 타임라인) | **프리미어 프로** |
| **상세 속성·기능 메모**(인스펙터)·**레이어**(하이어라키) | **유니티** |
| 최종 **인코딩**(핸드오프) + 에셋 아카이브 | — |

화면 구조: **좌 = 레이어(하이어라키) / 중앙 = 프로그램 모니터(캔버스) / 우 = 속성(인스펙터) / 하단 = 타임라인 / 상단 = 시퀀스 탭.**

---

## 1. 핵심 구조: 시퀀스 › 씬 › 요소

- **시퀀스**(상단 탭, `SEQ1`…): 큰 단위(막). 코드명은 자동·불변(장치/시리얼이 이 번호를 씀). **이름만** 수정.
- **씬**(파워포인트 슬라이드처럼): 한 시퀀스 안의 화면들. 예) SEQ1 → 씬1 "Press Any Key" → 씬2 "로딩" → 씬3 "사용설명".
- **요소(박스)**: 씬 안의 배경·이미지·텍스트·프리팹.

---

## 2. 전체 흐름

```
① 구상    → 시퀀스/씬을 만든다 (파워포인트 슬라이드 짜듯)
② 그래픽  → 이미지를 AI로 만들거나 준비 (글자 없이 = NO-TEXT)
③ 배치    → 프로그램 모니터(캔버스)에 박스로 올리고 정렬
④ 흐름    → 하단 타임라인에서 인터랙션 순서·전환·상태를 짠다
⑤ 메모    → 인스펙터에 기능/상호작용/입력버튼을 말로 적는다 (논코딩)
⑥ 인코딩  → 시퀀스를 골라 인코딩 → .pimmgame.json + 에셋 폴더
⑦ 빌드    → 핌플레이어(Unity)에서 인코딩 불러오기 → Play로 확인 → Build
⑧ 수정    → 툴에서 고치고 다시 인코딩 → 다시 적용
```

당신은 ①~⑥ + ⑧. ⑦은 처음 한 번만 익히면 반복됩니다(→ `guide-cowork-unity.md`, `distribution-and-build.md`).

---

## 3. 단계별 사용법

### ① 시퀀스 · 씬 (구상)
- 상단 **시퀀스 탭 `+`** 로 큰 단위 추가(SEQ# 자동). 표시 이름만 더블클릭 수정.
- 좌측 **씬 목록**에서 씬 추가/이름변경/순서. 선택한 씬을 캔버스가 편집.

### ② 그래픽 (NO-TEXT 규칙)
- AI 이미지엔 **글자를 넣지 않는다.** 글자는 텍스트 박스로 올린다(수정·정렬 자유). 툴이 프롬프트에 "글자 없이"를 자동으로 붙여준다.

### ③ 배치 (일러스트처럼)
박스 종류:
- **배경 이미지** 버튼: 화면 전체(1920×1080) 배경을 한 번에. 자동으로 맨 아래·잠금.
- **텍스트 박스**: `static`(고정 글자) / `dynamic`(상황별 글자 — "정답 시 → CLEAR!" 처럼 여러 개).
- **이미지 박스**: 자기 좌표 박스 안에 놓이는 그림(배경·UI). `button`/`image` 선택.
- **프리팹 박스**: 여러 개가 **같은 이미지·같은 크기를 공유**하는 오브젝트(인터랙션·기능용). 하나를 바꾸면 인스턴스 전부 바뀜.
- **정렬/분배**(일러스트식): 여러 박스 선택(Shift+클릭 또는 드래그) → 좌/중/우·상/중/하 정렬, 균등 분배, 크기 맞춤. 기준은 선택영역/캔버스 토글.
- 좌표·크기는 캔버스에서 끌거나 **인스펙터 X/Y/W/H에 숫자 직접 입력**. **Ctrl+Z 되돌리기**, 우클릭 메뉴, 스마트 정렬 가이드(분홍선) 지원.

### ③-1 상태(배리에이션)
- 이미지/프리팹 박스는 **상태1·상태2…** 를 가질 수 있다(인스펙터의 "상태" 카드). 버튼 눌림/정답·오답/켜짐·꺼짐 등을 **박스 하나로** 표현 → 하이어라키가 깔끔.
- 상태 전환은 타임라인 인터랙션과 연결: "인터랙션2 하면 → [버튼]을 [상태2]로".

### ④ 타임라인 (인터랙션 순서 — 시간 아님!)
- 하단 타임라인의 **가로축 = 플레이 중 인터랙션 순서**(인터랙션1→2→3, 입력마다 넘어가는 단계). 초 단위 아님.
- **트랙(세로)** = 레이어: 배경/UI·버튼/텍스트/BGM/SFX (색으로 구분).
- **클립(막대)** = 그 요소가 유지되는 인터랙션 구간 = **연속성**. 길게 = 유지(다음 씬으로 이어짐, 깜빡임 없음), 짧게 = 그 구간만.
- **인터랙션 마커** 클릭 → "인터랙션N 하면 ~" 편집: 전환(컷/페이드/디졸브)+메모, 상태전환, SFX, 다음 씬으로, **엔드마크**(시퀀스 종료).
- 요소의 **연속성**(유지/변경/등장/퇴장)은 인스펙터 드롭다운 또는 클립 길이로 지정.

### ⑤ 소리 + 메모 (논코딩)
- 툴바 **SFX/BGM 추가**. **BGM = 시퀀스**(장면 내내 지속), **SFX = 인터랙션**(순간 재생, "정답 시 → correct.wav").
- 인스펙터 상호작용 목록 → 항목 클릭 → **메모**로 기능·입력버튼(G1 조이스틱/G2 휠/G3 듀얼레버/G4 싱글레버/G5 3×3/G6 4×4)·프롬프트를 적는다.

### ⑥ 인코딩 (최종 산출)
- 툴바 **🎬 인코딩** → 시퀀스 선택 → **`SEQ#.pimmgame.json`**(에셋·소리·좌표·씬·인터랙션·상태·전환이 전부 담긴 자체완결 파일) + 에셋 아카이브 폴더.
- **리스킨 사전점검**: 기존 메커니즘이면 "리스킨 호환"(초록), 새 방식이면 "신규 메커니즘 필요"(주황) 배지.
- 그 외 내보내기: **데이터 내보내기**(레이아웃 JSON), **좌표이미지 내보내기**(SVG, 박스별 교체 슬롯).
- 저장: 서버 있으면 Drive `PIMMplayer_JSON` 폴더에 바로, 없으면 저장창/다운로드.

### ⑦ 빌드 (핌플레이어) — 처음 한 번만 익히면 반복
- 핌플레이어 Unity 프로젝트에서 **PIMM ▸ 게임 인코딩 불러오기** → 인코딩파일 선택 → 에셋/config 자동 적용 → **Play로 직접 QC** → 문제 없으면 Build. (배포/설치는 `distribution-and-build.md`.)

### ⑧ 수정
- 툴에서 고치고(20분마다 자동 임시저장, 복구 지원) 다시 인코딩 → 유니티에 다시 불러오기.

## 4. 안전장치 & FAQ
- **자동저장**: 변경 시 저장 + 20분마다 임시저장. 용량 초과 시 상단 경고 배너 → 인코딩/데이터 내보내기로 백업.
- **글자 흐릿** → AI 이미지에 글자 넣지 말 것(텍스트 박스로).
- **박스 안 움직임** → 하이어라키 🔒 잠금 확인(배경은 기본 잠금).
- **씬 전환이 뚝뚝 끊김** → 그 요소의 연속성을 "유지"로(같은 오브젝트 재사용 → 깜빡임·BGM 재시작 없음).
- **새 게임 방식** → 리스킨 범위를 넘음. 인코딩이 "신규 메커니즘 필요"로 표시하면 Cowork/개발자와 함께.

## 5. 한 문장 요약
**시퀀스·씬으로 구상, NO-TEXT 이미지로 배치·정렬, 타임라인으로 인터랙션 흐름·연속성, 인스펙터에 기능 메모 → 인코딩 → 핌플레이어에서 직접 빌드.**
