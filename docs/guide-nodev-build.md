# PIMM UnityGameCreator — 무개발 사용자 가이드

> **목표**: 개발 지식이 전혀 없어도, 게임을 명확히 구상하고 그래픽 에셋만 준비하면
> 이 툴 하나로 **핌플레이어(PIMMplayer)를 유니티로 빌드하고, 나중에 수정**까지 할 수 있다.
> 이 문서는 "코딩을 모르는 기획자/디자이너"를 대상으로 한다.

---

## 0. 먼저 알아둘 것 — 이 툴이 하는 일과 못 하는 일

핌플레이어는 이미 **5종의 게임 메커니즘**(순발력·추리·협동·기억·조작)을 코드로 갖고 있다.
이 툴은 그 위에 **당신의 게임을 얹는 도구**다.

| 당신이 할 수 있는 것 (코딩 0) | 개발자/Cowork가 필요한 것 |
|---|---|
| 기존 5종 메커니즘을 **리스킨**(배경·버튼·이미지·글자·소리 교체) | **새로운 게임 방식**(기존에 없는 규칙) |
| 화면 레이아웃·좌표·크기 배치 | 새 입력장치(기존 G1~G6 외) 배선 |
| 텍스트/버튼/이미지/배경/효과음/BGM 구성 | 물리엔진·네트워크 등 신규 기능 |
| 입력 버튼(조이스틱·휠·레버·스위치 등) 맵핑 | — |
| 핸드오프 파일 내보내기 → 유니티 적용 | 최초 유니티 프로젝트 셋업 1회 |

> **핵심 규칙**: "기존 게임의 껍데기를 바꾸는 것"은 당신 혼자 가능. "게임 규칙 자체를
> 새로 만드는 것"은 Cowork(대화형 AI)나 개발자와 함께. → 자세히는 `guide-cowork-unity.md`.

## 1. 전체 흐름 (한눈에)

```
① 게임 구상        → 비트시트 탭에서 시퀀스(장면) 순서를 짠다
② 그래픽 준비      → 에셋을 AI로 만들거나(NO-TEXT 규칙) 직접 준비
③ 배치            → 레이아웃 탭 1920×1080 캔버스에 박스로 올린다
④ 맵핑·메모        → 인스펙터에 상호작용/입력버튼/소리/프롬프트를 적는다
⑤ 핸드오프 내보내기 → 핸드오프 JSON + SVG + config 내보내기
⑥ 유니티 빌드      → 파일을 핌플레이어 프로젝트에 넣고 런타임 시연
⑦ 수정            → 툴에서 고치고 다시 내보내기 → 다시 적용
```

당신은 **①~⑤ + ⑦**을 담당한다. ⑥의 최초 1회 셋업만 Cowork/개발자 도움을 받으면,
이후 수정은 스스로 반복할 수 있다.

## 2. 화면 구조 (유니티 에디터 방식)

```
┌───────────────────────────────────────────────────────────────┐
│ [상단] 시퀀스 탭:  SEQ1 룰렛 | SEQ2 순발력 | + (프리미어처럼 추가) │
│ [상단] 파이프라인 탭: BEATSHEET · ASSET · MANAGE · LAYOUT · ...  │
├──────────────┬──────────────────────────────┬──────────────────┤
│ 하이어라키    │   씬(캔버스 1920×1080)        │  인스펙터         │
│ (레이어 트리) │   박스를 드래그/리사이즈       │  선택한 박스 속성  │
│ 🔒잠금 👁숨김 │                              │  Transform/메모   │
└──────────────┴──────────────────────────────┴──────────────────┘
```

- **좌측 하이어라키**: 모든 요소(박스)가 트리로 보인다. 각 항목에 🔒잠금·👁숨김.
  - 잠그면(🔒) 캔버스에서 실수로 안 움직인다(일러스트/포토샵 레이어 잠금과 같음).
- **중앙 씬**: 실제 배치 화면. 1920×1080이 핌플레이어 화면 기준.
- **우측 인스펙터**: 고른 박스의 **좌표(X/Y/W/H) 직접입력** + **메모(논코딩 프롬프트)**.

## 3. 단계별 사용법

### ① 비트시트 (BEAT SHEET) — 게임 구상
- 시퀀스 = 장면 하나(예: 로비 → 룰렛 → 순발력게임 → 결과).
- **상단 시퀀스 탭의 `+`** 로 장면을 늘린다. 각 탭은 독립된 화면이다.
- 시퀀스 코드명 **SEQ1, SEQ2…는 자동으로 붙고 바꿀 수 없다**(뒤에서 아두이노/시리얼이 이 번호를 쓴다). **표시 이름만 더블클릭해서** 바꾼다(예: SEQ2의 이름을 "순발력").

### ② 에셋 만들기 (ASSET CREATE) — 그래픽 준비
- 이미지를 **AI로 생성**하거나 직접 준비한다.
- **NO-TEXT 규칙**: AI 이미지에는 **글자를 넣지 않는다**. 글자는 반드시 툴의 **텍스트 박스**로 올린다(수정·다국어·정렬이 자유로워짐). 툴이 이미지 프롬프트에 자동으로 "글자 없이" 지시를 붙여준다.
- 검수 6항목(해상도·투명도·여백 등)을 체크한다.

### ③ 레이아웃 (LAYOUT) — 캔버스에 배치
박스는 3종류:
- **배경 이미지 버튼**: 누르면 화면 전체(1920×1080) 배경이 한 번에 생긴다. 자동으로 맨 아래·잠금.
- **텍스트 박스** (= 유니티 텍스트/TextMesh):
  - `static`: 고정 글자(예: 타이틀).
  - `dynamic`: 상황에 따라 바뀌는 글자. 인스펙터에서 "정답 시 → CLEAR!" 처럼 **조건→글자**를 여러 개 등록.
- **에셋 박스** (= 버튼 또는 이미지):
  - `button` 또는 `image`를 고른다.
  - 이미지 넣기: **드래그앤드롭** 하거나 **브라우즈 버튼**으로 파일 선택. 둘 다 됨.
- 위치·크기: 캔버스에서 끌어도 되고, **인스펙터 상단 X/Y/W/H 칸에 숫자 직접 입력**(일러스트 속성창처럼). 양쪽이 실시간 동기화.

### ④ 인스펙터 메모 — 상호작용·입력·소리 (논코딩)
박스를 고르면 인스펙터에 **상호작용/기능 목록**이 나온다. 항목을 눌러 **메모**를 적는다.
이게 "코딩 대신 말로 적어두는" 방식이다. 예시:
- 버튼 박스 → "이 버튼 누르면 다음 시퀀스로" + **입력 맵핑**(어떤 물리버튼인지) + **효과음(SFX)** 연결.
- **효과음(SFX)** 은 특정 순간에 울리므로 **해당 상호작용에 연결**(예: "정답 시 → correct.wav").
- **BGM**(배경음)은 장면 전체에 깔리므로 **시퀀스 단위**(하이어라키 최상단 시퀀스 노드의 BGM 슬롯).
- 툴바의 **SFX 추가 / BGM 추가** 버튼으로 소리 파일을 등록한다.

> 입력 버튼 종류(핌플레이어 실제 장치): G1 조이스틱+6버튼 / G2 휠 / G3 듀얼레버 / G4 싱글레버 /
> G5 3×3 스위치 / G6 4×4 그리드. 어떤 상호작용이 어떤 장치의 어떤 버튼인지 메모에 적는다.

### ⑤ 핸드오프 내보내기
- **[핸드오프 JSON 내보내기]** 버튼 → 저장 위치를 고른다(브라우즈). 파일명에 `PIMMplayer_JSON`이 들어간다.
- **[SVG 내보내기]** → 일러스트레이터에서 열면 (1) 전체가 한 아트보드, (2) 박스마다 개별 아트보드가 생긴다. 나중에 에셋을 갈아끼울 때 슬롯 역할.
- 서버가 켜져 있으면 Drive의 `PIMMplayer_JSON` 폴더에 바로 저장할 수도 있다(설정 시).

### ⑥ 유니티에 적용 (최초 1회만 도움 필요)
- 내보낸 config들을 핌플레이어 프로젝트의 `StreamingAssets`에 넣는다.
- 이미지/소리 에셋을 프로젝트에 넣고, 좌표는 핸드오프의 `unity.anchorMin/Max`(이미 계산돼 있음)를 쓴다.
- 유니티에서 **Play(런타임)** 로 실제 시연·검수.
- 최초 연결(어떤 config를 어디에 두는지)만 `guide-cowork-unity.md`대로 한 번 익히면, 이후 ⑦은 반복.

### ⑦ 수정하기
- 툴에서 박스를 고치고(위치·이미지·글자·소리·메모) → 다시 내보내기 → 유니티에 덮어쓰기 → 다시 Play.
- localStorage에 자동 저장되므로 브라우저를 닫아도 작업이 남는다. 중요한 버전은 핸드오프 파일로 따로 보관.

## 4. 자주 막히는 지점 (FAQ)

- **글자가 흐릿/깨져요** → AI 이미지에 글자를 넣지 마세요. 글자는 텍스트 박스로.
- **박스가 안 움직여요** → 하이어라키에서 🔒 잠겼는지 확인(배경은 기본 잠금).
- **시퀀스 번호를 바꾸고 싶어요** → 코드명(SEQ#)은 못 바꿉니다(장치 연동 때문). 표시 이름만 바꾸세요.
- **유니티에서 위치가 안 맞아요** → 핸드오프의 `unity.anchorMin/Max`를 그대로 쓰세요(Y축이 뒤집혀 계산돼 있음).
- **새로운 게임 방식을 넣고 싶어요** → 리스킨 범위를 넘습니다. Cowork/개발자와 함께(`guide-cowork-unity.md`).

## 5. 한 문장 요약
**구상은 비트시트, 그래픽은 NO-TEXT로, 배치는 캔버스, 코딩은 메모로, 결과는 핸드오프로.**
그러면 개발 없이도 핌플레이어가 만들어지고, 언제든 다시 고칠 수 있다.
