# PIMMotion 플랫폼 아키텍처 (북극성)

> PIMMotion은 하나의 툴이 아니라 **여러 에디터 에이전트를 품는 플랫폼**이다.
> 첫 관문(마더페이지/허브)에서 **Forge**(빠른 진입)와 **Track**(전체 공정) 두 방식으로 접근한다.
> 이 문서는 그 위계와 진입 구조를 고정한다. (Drive 실폴더 구조 기준)

---

## 1. 에디터 에이전트란

**에디터 = 비경험자·초심자가 전문툴(어도비·유니티·스케치업 등)을 코워크(대화형 AI)로
설계·작업하게 돕는 에이전트.** 전문툴의 진입장벽을 낮춰, "무엇을 만들지"는 사람이 정하고
"어떻게 만드는지"는 에디터+코워크가 돕는다.

- 지금 가동(LIVE) 중인 에디터: **게임 에디터 에이전트**(Unity/PIMMplayer 콘티·레이아웃·인코딩)
  = `tool/PIMM_UnityGameCreator.ver1.6.html`.
- 향후: 어도비 에디터, 스케치업 에디터 등(🚧).

## 2. Drive 실구조 — 필드 & 섹터

최상위는 **색상 필드(Field)**, 그 안에 **섹터(Sector)**.

```
[0.제로필드:휴지통] trash
[1.그린필드:프레임워크] PIMM_framework        ← 4대 핵심 섹터
   ├─ [1.플로직_섹터] Plogic        = 마스터로직
   ├─ [2.포피스_섹터] Poffice       = 사무체계시스템
   ├─ [3.파트웍_섹터] Partwork      = 실제공정처리과정 (빈약 🚧, 추후 Track의 뼈대)
   └─ [4.피모션_섹터] PIMM-cowork   = 실전작업툴 (에디터 에이전트들)
[2.블루필드:아카이브] PIMM_archive   ├─ 개인DB_섹터 / 에셋_섹터
[3.옐로필드:RnD] PIMM_invent         ├─ 레퍼런스_섹터 / 아웃풋_섹터(PIMMplayer_JSON 등)
[4.퍼플필드:로그라인] PIMM_Log        └─ 리포트로그_섹터
```

- **필드** = 큰 도메인(프레임워크/아카이브/RnD/로그).
- **섹터** = 필드 안의 기능 단위.
- **4대 프레임워크 섹터**(Plogic/Poffice/Partwork/PIMMotion)가 플랫폼의 뼈대.

---

## 3. 4대 프레임워크 (핌코프 체계)

| 섹터 | 뜻 | 역할 | 상태 |
|---|---|---|---|
| **Plogic (플로직)** | 마스터로직 | 최상위 판단·원칙 | 🚧 |
| **Poffice (포피스)** | 사무체계시스템 | 사무/운영 체계 | 🚧 |
| **Partwork (파트웍)** | 실제공정처리과정 | 공정 흐름(Track의 뼈대) | 🚧 (빈약) |
| **PIMMotion (피모션)** | 실전작업툴 | **에디터 에이전트들** | 게임에디터 LIVE, 나머지 🚧 |

## 4. 진입 구조 — Forge vs Track (병렬)

첫 화면(마더페이지) = **로고 + 카테고리 버튼**. 두 접근 방식이 병렬로 존재한다.

- **Forge** — 특정 에디터/시스템으로 **바로 진입**(빠른 접근). 카드 그리드.
  - 4대 섹터 카드 → 피모션 카드에서 **에디터 에이전트 카드**(게임에디터 LIVE + 나머지 🚧).
- **Track** — 테마의 **최초 공정부터 끝까지** 전체 파이프라인 진입.
  - 뼈대는 **Partwork(실제공정)** — 아직 빈약해서 대부분 🚧. Partwork가 채워지면 Track이 살아난다.

```
        ┌──────────── 마더페이지(허브) ────────────┐
        │  로고 · "에디터란?" 안내                    │
        │  [Forge] ↔ [Track]  (병렬 토글)             │
        ├───────────────────┬────────────────────────┤
   Forge│ Plogic🚧 Poffice🚧 │  Track: 기획→설계→제작→   │
        │ Partwork🚧         │   현장→아카이빙 (대부분🚧) │
        │ PIMMotion ▼        │                          │
        │   └ 게임에디터 LIVE →ver1.1                   │
        │   └ 어도비🚧 스케치업🚧 …                      │
        └───────────────────┴────────────────────────┘
```

## 5. 통합 워크플로우 (여러 에디터/에이전트 통합)

- 허브는 **진입점**이자 **통합 레이어**. 에디터 목록을 **데이터(배열/JSON)**로 정의 →
  카드가 그 배열에서 렌더 → **에디터 추가 = 배열 한 줄**.
  ```json
  { "id":"gamecreator", "name":"게임 에디터 에이전트",
    "desc":"유니티/핌플레이어 콘티·레이아웃·인코딩", "status":"live",
    "launch":"./PIMM_UnityGameCreator.ver1.6.html" }
  ```
- 각 에디터는 **자체완결 산출(핸드오프/인코딩)** 을 내고 → 코워크가 바이브코딩으로 실제 빌드
  (게임에디터의 경우 `docs/encoding-and-build.md`). 다른 에디터도 같은 패턴(설계→핸드오프→코워크 빌드).
- 산출물은 옐로필드 **아웃풋 섹터**로 모이고, 로그는 퍼플필드로.
