# Cowork + Unity 실전 워크플로우 가이드 (ver1.0)

> 유니티를 켜 둔 채 Cowork(대화형 Claude)와 함께 게임을 만드는 실전 루프.
> PIMM UnityGameCreator 툴이 설계·인코딩의 "손", Cowork가 빌드/신규코드의 파트너.
> 배포·임포터는 `distribution-and-build.md`, 인코딩 규격은 `encoding-and-build.md` 참조.

---

## 0. 역할

| 주체 | 역할 |
|---|---|
| **당신** | 구상 · 배치 · 타임라인/상태/연속성 · 메모 · **인코딩** · Play로 직접 QC |
| **툴(HTML)** | 시퀀스>씬>요소, 정렬, 타임라인, 상태, 인코딩(.pimmgame.json)+에셋아카이브 |
| **Cowork** | 함께 기획, 유니티 데모/신규 C#, 인코딩 해석·적용(바이브코딩) |
| **Unity(핌플레이어)** | 인코딩 임포트 → Play 시연 → Build |

분업: **툴 = 리스킨(껍데기·흐름), Cowork = 데모/신규 로직(뼈대), Unity = 검수.**

---

## 1. 좌표 우선 루프

```
기획(대화) → Cowork가 유니티 데모(하드코딩 좌표) → 데모 좌표 확보
  → 툴에서 그 좌표로 씬·박스 배치(인스펙터 X/Y/W/H 직접입력)
  → 그래픽(AI, NO-TEXT) 생성 → 상태(배리에이션) 등록 → 타임라인으로 인터랙션 흐름·연속성
  → 인코딩(.pimmgame.json) → 핌플레이어에 임포트 → Play로 QC → 수정 반복
```

핵심: **데모가 먼저.** 데모의 좌표를 기준으로 에셋을 만들고, 툴에서 그 자리에 배치·인코딩한다.

---

## 2. 단계별

### STEP 1. 기획 (대화)
Cowork와 규칙·씬 순서·승패를 잡고, 툴 **시퀀스/씬**에 옮긴다(SEQ# 자동).

### STEP 2. Cowork 데모 제작
- 기존 메커니즘(순발력/추리/협동/기억/조작) 중 맞는 것으로 데모 씬. 요소 RectTransform 좌표가 하드코딩됨 → 다음 단계 기준.
- **리스킨 vs 신규 판단**: 기존 메커니즘이면 config+에셋만(당신 주도). 새 규칙이면 Cowork가 C# 추가.

### STEP 3. 좌표 → 툴
데모 좌표를 툴 인스펙터 X/Y/W/H에 직접 입력. 배경은 [배경 이미지]. 여러 개는 일러스트식 정렬로 맞춤.

### STEP 4. 이미지 프롬프트 (NO-TEXT)
- 글자 금지(텍스트 박스로). 툴이 프롬프트에 "글자 없이" 자동 프리픽스.
- 박스의 정확한 픽셀 크기·비율·아트 스타일을 프롬프트에 반영. 사용한 프롬프트는 **인스펙터 메모에 저장**(재생성·수정 시 재사용).
- 생성 이미지를 박스에 드래그앤드롭/브라우즈로 삽입.

### STEP 5. 상태 · 타임라인 · 연속성
- **상태(배리에이션)**: 버튼 눌림/정답·오답 등을 상태1·2…로. 프리팹은 정의 공유(인스턴스 전파).
- **타임라인**(가로축=인터랙션 순서): 인터랙션 마커에 전환(디졸브/페이드)+메모, `setState`(상태 전환), SFX, 엔드마크.
- **연속성**: 씬을 넘어 유지할 요소는 "유지"로 → 런타임이 같은 오브젝트 재사용(배경 깜빡임·BGM 재시작 방지).

### STEP 6. 인풋 버튼 맵핑
- 상호작용 메모에 "이 버튼 → 어느 장치의 어느 신호"(G1 조이스틱+6버튼/G2 휠/G3 듀얼레버/G4 싱글레버/G5 3×3/G6 4×4).
- **SEQ# 코드명이 중요**: 시리얼/아두이노가 SEQ#+신호ID로 입력을 라우팅. 그래서 코드명 불변. 내보낸 `combo_input_registry.json`을 Cowork/유니티가 배선에 사용.

### STEP 7. 인코딩
- 툴 **🎬 인코딩** → 시퀀스 선택 → `SEQ#.pimmgame.json`(자체완결) + 에셋 아카이브 폴더. 리스킨 사전점검 배지 확인.
- Drive `PIMMplayer_JSON` 폴더에 저장(서버 연동) 또는 다운로드. Cowork는 Drive/파일로 이 번들을 읽는다.

### STEP 8. 유니티 임포트 · Play · 검수
- 핌플레이어에서 **PIMM ▸ 게임 인코딩 불러오기** → 인코딩파일 선택 → 에셋/config/좌표/소리 자동 적용.
- **Play로 직접 QC**: 좌표 정합, 이미지·상태 전환, 입력 반응, SFX·BGM 타이밍, 씬 전환·연속성, 판정.
- 수정사항 → 툴로 돌아가 고치고 재인코딩. 데모 좌표가 바뀌면 STEP 2로. **신규 메커니즘이 필요하다고 뜨면 그 부분만 Cowork 요청.**

---

## 3. Cowork 연동 (있으면 왕복이 짧아짐)
- **툴 내 Claude 챗**(서버 시): "이 프롬프트 다듬어줘 / 이 입력 맵핑 검증해줘". `POST /api/chat`(키 서버보관).
- **Drive 저장**: 인코딩/데이터를 `PIMMplayer_JSON` 동기폴더에 저장 → Cowork가 즉시 읽음. `PIMM_DRIVE_EXPORT_DIR`.
- **빌드 계약**: Cowork의 결정론적 빌드 절차는 `encoding-and-build.md` §3. 리스킨 우선, 에셋 기반 애니메이션, 신규 C#은 플래그된 부분만.

## 4. 체크리스트 (한 루프)
- [ ] 시퀀스·씬 정리(SEQ# 자동) / [ ] Cowork 데모 좌표 확보 / [ ] 툴에 좌표 입력·정렬
- [ ] NO-TEXT 이미지 + 프롬프트 메모 / [ ] 상태(배리에이션) 등록
- [ ] 타임라인 인터랙션·전환·연속성 / [ ] 입력 맵핑(G1~G6)+SEQ# / [ ] SFX·BGM
- [ ] 인코딩(.pimmgame.json)+아카이브 → [ ] 유니티 임포트 → Play QC → 수정 반복

## 5. 한 문장 요약
**데모 좌표 기준으로 NO-TEXT 이미지를 리스킨하고, 상태·타임라인·연속성으로 연출하고, 입력을 SEQ#로 맵핑해 인코딩 → 유니티에 임포트하면 당신이 Play로 검수한다.**
