# Cowork + Unity 실전 워크플로우 가이드

> 실제로 GAMZA가 작업하는 방식 — **유니티를 켜 둔 채 Cowork(대화형 AI)와 함께**
> ① 이미지 생성 프롬프트 작업 → ② 인풋 버튼 맵핑 → ③ 유니티 안에서 런타임 시연 —
> 을 반복하는 루프를 문서화한다. PIMM UnityGameCreator 툴이 이 루프의 "손"이 된다.

---

## 0. 등장 인물과 역할

| 주체 | 역할 |
|---|---|
| **당신(기획/디자인)** | 게임을 구상하고, 툴로 배치하고, 결과를 검수 |
| **PIMM UnityGameCreator (툴)** | 레이아웃·좌표·메모·핸드오프 산출(JSON/SVG/config)의 손 |
| **Cowork (대화형 Claude)** | 함께 기획을 잡고, **유니티 데모/C#을 만들고**, 핸드오프를 해석해 적용 |
| **Unity(핌플레이어)** | 최종 런타임. 실제로 플레이·검수하는 곳 |

핵심 분업: **툴 = 리스킨(껍데기)**, **Cowork = 데모/신규 로직(뼈대)**, **Unity = 검수**.

---

## 1. 전체 루프 (좌표 우선 방식)

당신이 정리한 실제 순서:

```
기획(대화)                → Cowork와 대화로 게임을 잡는다
  └▶ Cowork가 유니티 데모 제작 (하드코딩 좌표로 동작하는 데모)
       └▶ 데모의 좌표값 확보  ← 이 좌표가 에셋 준비의 기준
            └▶ 에셋 이미지 좌표 준비 (툴에서 박스로)
                 └▶ 그래픽 작업(AI 생성, NO-TEXT)
                      └▶ 레이아웃툴로 레이어 계층 정렬
                           └▶ 데모에 적용(에셋 교체 = 리스킨)
                                └▶ 유니티 런타임 검수
                                     └▶ 수정사항 → 다시 위로
```

포인트: **데모가 먼저**다. 데모의 하드코딩 좌표를 기준으로 에셋을 만들고, 툴에서 그 좌표에
맞춰 배치한 뒤, 이미지를 그 자리에 갈아끼운다.

---

## 2. 단계별 실전

### STEP 1. 기획 (Cowork와 대화)
- Cowork와 대화로 게임 규칙·장면 순서·승패조건을 잡는다.
- 결정된 장면을 툴 **비트시트 탭**에 시퀀스로 옮긴다(SEQ1, SEQ2… 자동).
- 산출: 시퀀스 목록 + 각 시퀀스의 목표/판정 개요.

### STEP 2. Cowork가 유니티 데모 제작
- Cowork가 핌플레이어의 기존 메커니즘(순발력/추리/협동/기억/조작) 중 맞는 것을 골라 **데모 씬**을 만든다.
- 이때 요소들의 **RectTransform 좌표가 하드코딩**된다(데모니까). 이 좌표가 다음 단계의 기준.
- **리스킨 vs 신규 판단**: 기존 메커니즘으로 되면 config+에셋만으로 끝(당신 주도). 새 규칙이면 Cowork가 C#을 새로 씀.

### STEP 3. 데모 좌표 → 툴에 옮기기
- 데모에서 각 요소의 위치/크기를 확인한다.
- 툴 레이아웃 탭에서 같은 좌표로 박스를 만든다. **인스펙터 X/Y/W/H에 데모 좌표를 직접 입력**하면 정확히 맞는다.
- 배경은 [배경 이미지] 버튼(1920×1080 전체).

### STEP 4. 이미지 생성 프롬프트 작업 (NO-TEXT)
- 각 박스 자리에 들어갈 이미지를 AI로 생성한다.
- **프롬프트 규칙**:
  - **글자 금지**(NO-TEXT). 글자는 텍스트 박스로 따로. 툴이 프롬프트에 자동으로 "no text, no letters"류 프리픽스를 붙인다(prompt_bundle.json).
  - 박스의 **정확한 픽셀 크기·비율**을 프롬프트에 반영(예: "280×120 버튼, 투명 배경 PNG").
  - 배경/버튼/아이콘의 **아트 스타일 일관성**을 한 문장으로 고정해 매번 붙인다.
- 각 박스 인스펙터의 **메모(프롬프트)** 에 사용한 프롬프트를 저장 → 나중에 재생성·수정 시 그대로 재사용.
- 생성 이미지를 박스에 **드래그앤드롭** 또는 **브라우즈**로 삽입.

### STEP 5. 레이어 계층 정렬 (레이아웃툴)
- 하이어라키에서 z-order(앞뒤)를 맞춘다. 배경은 맨 아래, UI/버튼은 위.
- 확정된 요소는 🔒 잠가서 실수 이동 방지.
- 완료되면 **SVG 내보내기** → 일러스트에서 아트보드1(전체) + 박스별 아트보드(교체 슬롯) 확인.

### STEP 6. 인풋 버튼 맵핑
핌플레이어는 물리 컨트롤러로 논다. 각 상호작용을 실제 장치 버튼에 연결한다.

| 슬롯 | 장치 | 신호 예 |
|---|---|---|
| G1 | 조이스틱 + 6버튼 | 방향 + btn1~6 |
| G2 | 휠(wheel) | 회전값 |
| G3 | 듀얼 레버 | lever L/R |
| G4 | 싱글 레버 | lever |
| G5 | 3×3 스위치 | sw(0~8) |
| G6 | 4×4 그리드 | grid(0~15) |

- 툴 인스펙터의 상호작용 메모에 **"이 버튼 → 어느 장치의 어느 신호"** 를 적는다.
- **시퀀스 코드명(SEQ#)이 여기서 중요**: 시리얼/아두이노 파싱 코드가 SEQ# + 신호ID로 입력을 라우팅한다. 그래서 코드명은 불변.
- 내보낸 `combo_input_registry.json`(보드/신호/게임슬롯 맵)을 Cowork/유니티가 읽어 배선.

### STEP 7. 데모에 적용 (에셋 교체 = 리스킨)
- 핸드오프 JSON + config + 이미지/소리 에셋을 핌플레이어 프로젝트에 넣는다.
  - config → `Assets/StreamingAssets/...` (theme_config / config(SeqData) / combo_input_registry / combo_defaults / 시퀀스별 layout).
  - 좌표 → 핸드오프의 `unity.anchorMin/Max`(Y-flip 계산 완료).
  - 이미지/소리 → 프로젝트 에셋으로, 데모의 자리표시자를 당신 에셋으로 교체.
- **여기 해석·적용은 Cowork가 맡을 확률이 높다** — 그래서 핸드오프는 기계가 읽기 쉽게 id/좌표/인덱스를 명시한다.

### STEP 8. 유니티 런타임 시연·검수
- 유니티 **Play**로 실제 컨트롤러 입력까지 시연.
- 확인: 좌표 정합 / 이미지 교체 반영 / 입력 버튼 반응 / SFX·BGM 타이밍 / 판정(성공·실패).
- 수정사항이 나오면 **툴로 돌아가 고치고 다시 내보내기**(STEP 3~7 반복). 데모 좌표가 바뀌면 STEP 2로.

## 3. Cowork를 이 루프에 어떻게 붙이나 (MCP/연동)

- **툴 내 Claude 챗** (서버 켜졌을 때): 툴 안에서 바로 Cowork에게 "이 시퀀스 프롬프트 다듬어줘",
  "이 입력 맵핑 검증해줘"를 물어볼 수 있다. → 서버 `POST /api/chat` (키는 서버 보관).
- **Drive 로컬폴더 연동**: 핸드오프를 `PIMMplayer_JSON` 동기폴더에 저장하면 Cowork가 Drive로 즉시 읽는다.
  → 서버 `POST /api/export/save` + `.env`의 `PIMM_DRIVE_EXPORT_DIR`. 모두 구글드라이브 앱을 쓰므로 **로컬 경로로 충분**.
- **핸드오프 계약**: Cowork가 해석할 산출물 구조는 `docs/backend-architecture.md`(§5) + 내보낸 파일 자체의 메타. 안정 주소 + 기계파싱 + 버전.

> 한 세션 안에서 "대화 기획 → 데모 → 배치 → 교체 → 검수"를 돌리려면, 위 두 연동(챗·Drive)이
> 있으면 왕복이 짧아진다. 없으면 파일을 수동으로 주고받아도 동일하게 동작한다.

## 4. 체크리스트 (한 루프)

- [ ] 비트시트에 시퀀스 정리(SEQ# 자동)
- [ ] Cowork 데모 좌표 확보
- [ ] 툴에 좌표 입력(X/Y/W/H)
- [ ] AI 이미지 생성(NO-TEXT, 정확한 픽셀) + 프롬프트 메모 저장
- [ ] 이미지 삽입(DnD/브라우즈), z-order·잠금 정리
- [ ] 입력 버튼 맵핑 메모(G1~G6) + SEQ# 연결
- [ ] SFX(상호작용) / BGM(시퀀스) 배치
- [ ] 핸드오프 JSON + SVG + config 내보내기(→ PIMMplayer_JSON)
- [ ] 유니티 적용(Cowork) → Play 검수 → 수정 반복

---

## 5. 한 문장 요약
**데모 좌표를 기준으로, NO-TEXT 이미지를 그 자리에 리스킨하고, 입력을 SEQ#로 맵핑해,
핸드오프로 넘기면 — Cowork가 유니티에 붙이고 당신이 런타임에서 검수한다.**
