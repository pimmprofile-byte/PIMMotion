# 타임라인 뷰 스펙 (게임에디터 ver1.6 — 프리미어 패러다임 복원)

> **핵심 교정(ver1.6)**: 타임라인 뷰는 **분기 그래프(플로우/노드)가 아니라 프리미어프로 트랙 레이아웃**이다.
> 이유 = 한 시점에 **여러 박스가 동시에 공존하는 것을 트랙으로 한눈에** 보는 게 목적. 게임뷰(프로그램
> 모니터)는 프리미어처럼 **상단**에, 트랙은 **하단**에. 성공/실패는 분기 노드가 아니라 **텍스트 메모**로 단순화.
> (원래 `tool-concept.md` §2 "타임라인=인터랙션 기준 트랙"과 정합. ver1.5의 플로우/분기 그래프는 폐기.)

---

## 0. 전체 워크플로우 (역할 분담 — 사용자 확정)

```
① 레이아웃 뷰   씬을 구성한다 (박스 배치·정렬·소리·이벤트 메모)        ← 사용자 (일러스트레이터식)
② 타임라인 뷰   씬박스를 조합해 순서를 맞춘다 (트랙으로 공존 확인)      ← 사용자 (프리미어식)
        │  = 인코딩/핸드오프(config)로 정리
        ▼
③ 코워크        정리된 내용을 확인·해석해 유니티에 빌드                ← 코워크 (로컬 유니티 접근)
        ▼
④ 유니티        재생하며 버그를 잡는다 (QC)                          ← 사용자/팀원 (로컬 유니티)
```

- 이 툴(①②)은 **설계·정리**까지. **실제 유니티 빌드(③)는 코워크**, **구동·QC(④)는 로컬 유니티**.
- 클라우드 세션의 나는 핌플레이어 **소스코드 작성/수정(push)** 담당, 유니티 실행은 안 함.

---

## 1. 위치 & 레이아웃 (프리미어프로형)

- 상단 탭 **"타임라인"** = 레이아웃 **바로 우측**.
- 화면 구성 = 프리미어프로:

```
┌───────────────────────────────────────────────┐
│   ▶재생   [ 프로그램 모니터 = 게임뷰 ]  (상단)     │  ← 플레이헤드 지점의 화면 구성(1920×1080 fit)
├──────────────┬────────────────────────────────┤
│ 저장소(Repo)  │  타임라인 트랙 (하단, 가로=인터랙션 순서) │
│  · 씬박스     │  🎬배경   [███ 배경A 유지 ██████]        │
│  · 박스칩     │  🅄UI/버튼 [PressKey]→[로딩]→[설명]       │
│  · 인터랙션   │  🅣텍스트  ["PRESS ANY KEY"]  ["LOADING"] │
│              │  🔊오디오  [████ BGM 유지 ████]  ♪ ♪      │
│              │  ├ 인터랙션1 ── 인터랙션2 ── 인터랙션3 ─┤ │
└──────────────┴────────────────────────────────┘
```

- **게임뷰(프로그램 모니터) = 상단**, **트랙 = 하단**. 프리미어의 모니터/타임라인 배치 그대로.
- 가로축 = **인터랙션 순서**(시간 아님). 플레이헤드를 인터랙션 지점에 놓으면 상단 모니터가 그 순간 화면을 렌더.

## 2. 저장소 (Repo) — 프리미어 미디어 빈

- 레이아웃에서 만든 **씬·박스**가 자동 파싱되어 Repo에 준비됨.
- **중심 항목 = 씬박스**(씬 통째). 그 외 개별 박스칩·인터랙션 마커(생성용)도 있음.
- Repo → 타임라인으로 **드래그앤드롭**.

## 3. 씬박스 드래그 = 씬 통째가 트랙에 올라감 (핵심)

- **씬박스 하나를 타임라인에 드롭 = 그 씬의 모든 박스가 각 트랙에 클립으로 함께 배치**된다.
  - 박스의 `role`(배경/버튼/이미지/텍스트) + 오디오로 트랙을 나눠 배치(배경 트랙·UI 트랙·텍스트 트랙·오디오 트랙…).
  - 이렇게 하면 "이 씬에서 동시에 뭐가 떠 있나"가 트랙 스택으로 한눈에 보임.
- 여러 씬박스를 가로로 이어 놓으면 = 씬 진행 순서. (씬1 블록 → 씬2 블록 …)
- 개별 박스칩 드래그도 가능(특정 박스만 추가). 하지만 **기본 작업단위는 씬박스**.

## 4. 트랙 & 클립 (프리미어 패러다임)

- **트랙(세로) = 요소 종류/레이어**, **클립(가로 막대) = 그 요소가 유지되는 인터랙션 구간**.
  - 유지=긴 막대(같은 오브젝트 재사용, 깜빡임 없음), 등장/퇴장=막대 시작/끝, 변경=막대 교체. (연속성 = 클립 길이)
- **트랜지션** = 클립 경계에 컷/페이드/디졸브 부착 + 메모.
- **플레이헤드** = 특정 인터랙션 선택 → 상단 프로그램 모니터가 그 구성 표시.
- 기존 하단 "연속성 트랙"의 개념을 이 뷰가 **정식 트랙 UI로 흡수**(중복 제거).

## 5. 인터랙션 마커 = 성공/실패 **텍스트 메모** (분기 그래프 없음)

> ver1.5의 성공/실패 **분기 노드는 폐기**. 직관성을 위해 **텍스트 메모 2칸**으로 단순화.

- 타임라인 가로축의 각 인터랙션 지점(마커)을 클릭하면 메모 패널:
  - **게임 진행방식**(선택, 짧은 설명)
  - **성공 시 실행작업** (텍스트) — 예: "정답 시 → 디졸브로 씬2 이동, 정답 SFX"
  - **실패 시 실행작업** (텍스트) — 예: "오답 시 → 화면 흔들림 후 재시도"
- **분기 라우팅·성공/실패 선택 팝업·다단계 goto 없음.** 사람이 읽는 **메모**일 뿐. 코워크가 이 메모를 읽고 핌플레이어 `onSuccess/onFail`을 구성(자동 라우팅 아님).

## 5.5. 재생(▶) 버튼 — 전체화면 게임뷰 (뷰별 상이, 유지)

재생 버튼 = **전체화면 게임뷰**(에디터 크롬 숨김, 현재 씬 1920×1080 fit). **ESC 복귀.** 뷰별로 다름:

| 뷰 | 재생 동작 |
|---|---|
| **레이아웃 뷰** | 디자인/그리드 프리뷰. **가변이미지박스는 상태1→상태n을 500ms마다 자동 스프라이트**(순환). (그리드 토글) |
| **타임라인 뷰** | **플레이헤드 스윕 재생.** 인터랙션1→N을 순서대로 훑으며 상단 프로그램 모니터(= 전체화면 게임뷰)가 각 구성으로 전환. 각 인터랙션의 성공/실패 메모는 주석으로 표시(분기 선택·팝업 없음). 가변이미지박스는 setState 구동. |

- 전체화면: `requestFullscreen` + `fullscreenchange`/ESC, 미지원 시 오버레이 폴백. 타이머 정리·에디터 상태 보존.
- 스프라이트 속도 상수 **500ms/상태**.

## 6. 내보내기(핸드오프)

- 타임라인 → **쇼 흐름 config**: `scenes[]`(씬 진행 순서) + 각 씬의 박스·트랙·클립 구간 + 인터랙션별 `{게임방식, 성공메모, 실패메모}` + 트랜지션.
- 코워크가 이 config를 읽어 핌플레이어 진행을 구성. **성공/실패 메모는 사람이 읽는 지시문**으로 전달(자동 분기 코드 생성 아님 — 리스킨 경계 유지).

## 7. QA 수용 기준 (프리미어 패러다임 기준으로 갱신)

- [ ] 레이아웃 = **게임뷰 상단 + 트랙 하단**(프리미어형)으로 렌더되는가
- [ ] **씬박스를 드롭하면 그 씬의 모든 박스가 트랙에 함께** 올라오는가(role별 트랙 분리)
- [ ] 여러 씬박스를 이어 **씬 진행 순서**를 만들 수 있는가
- [ ] 트랙/클립으로 **동시에 공존하는 박스들**이 한눈에 보이는가(유지=긴 막대 등)
- [ ] 인터랙션 마커에 **성공/실패 실행작업을 텍스트로 메모**할 수 있는가 (분기 그래프·선택 팝업 **없음**)
- [ ] 플레이헤드를 옮기면 상단 프로그램 모니터가 그 구성으로 갱신되는가
- [ ] 재생(타임라인 뷰)이 **플레이헤드 스윕**으로 전체화면 게임뷰를 훑는가, ESC 복귀·상태보존
- [ ] 재생(레이아웃 뷰)이 가변이미지박스 **500ms 스프라이트**로 도는가
- [ ] Repo 자동파싱이 레이아웃 변경(박스/씬 추가·삭제)을 반영하는가
- [ ] 내보낸 config에 씬 순서 + 트랙/클립 + 성공/실패 메모가 담겨 코워크가 읽을 수 있는가
- [ ] 초심자(파포 페르소나)가 **씬박스 드래그 + 인터랙션 메모**만으로 흐름을 짤 수 있는가

> 목표: **"여러 박스가 동시에 공존하는 씬 흐름"을 프리미어 트랙으로 직관적으로 짜고**, 성공/실패는
> 가벼운 메모로 남긴다. 분기 그래프처럼 무거운 로직은 넣지 않는다.

## 8. 기존 요소와의 관계

- 기존 하단 "🎞 타임라인(연속성 트랙)"은 이 뷰의 **정식 트랙 UI로 흡수/대체**(중복 혼선 제거).
- 씬(시퀀스>씬>박스), 이벤트(박스별 실행조건+명령), 상태(가변이미지박스)와 정합:
  타임라인 = **씬 진행 + 트랙 구성(상위 흐름)**, 이벤트/상태 = **박스 내부 동작**.
- ver1.5의 `PROJECT.timelineFlow`(분기 노드) 데이터는 **폐기/무시**하고, 트랙 기반 모델로 새로 정의(하위호환: 기존 프로젝트 로드시 빈 트랙으로 시작, 크래시 없이).
