# 타임라인 뷰 스펙 (게임에디터 ver1.5)

> 게임 **진행 순서 + 성공/실패 분기**를 시각적으로 짜는 플로우 시트. 프리미어 타임라인 은유 +
> 분기(노드) 개념. 완성된 흐름은 **핌플레이어 쇼 흐름(시퀀스 순서 + onSuccess/onFail 라우팅)**
> 으로 내보내진다. 빌드 전 QA로 "이 방식이 테스트플레이·구동방식을 전면 포착하는지" 검증한다.

---

## 1. 위치 & 구성
- 상단 탭 **"타임라인"** = 레이아웃 **바로 우측**(첫 화면에서 레이아웃 다음).
- 3영역: **저장소(Repo, 우측)** · **타임라인 플로우(중앙)** · **런(Run) 미리보기/팝업**.

## 2. 저장소 (Repo)
- 레이아웃에서 만든 **이미지박스·에셋·씬**이 **자동 파싱**되어 Repo에 준비됨(프리미어 미디어 빈 역할).
- 항목: 박스(이미지/텍스트/가변이미지/배경) 썸네일 + **씬박스**(씬 통째) + 인터랙션 박스(생성용).
- Repo → 타임라인으로 **드래그앤드롭** 배치.

## 3. 타임라인에 배치하는 것
| 배치 단위 | 의미 |
|---|---|
| **박스 클립** | 특정 박스를 화면에 배치(대기화면 구성 등) |
| **씬박스** | 씬 통째를 하나의 단위로 배치(상위 개념) |
| **인터랙션 박스** *(타임라인 전용)* | **성공/실패 분기 노드**. 게임 진행방식 + 성공·실패 판정 |

**흐름 예시**: 기본 대기화면 = 박스들 드래그 배치 → **인터랙션 박스**를 그 뒤에 → 트리거에 따라
분기 → 분기별로 다시 박스/씬 배치. (성공 경로 / 실패 경로가 갈라짐)

## 4. 인터랙션 박스 = 분기 노드
- 필드: **게임 진행방식 설명**(팝업에 표시), **트리거/판정 방식**, **성공 시 → (다음 씬/블록)**, **실패 시 → (다음 씬/블록)**.
- 분기 대상은 씬/타임라인 블록. (성공→씬2, 실패→재시도/종료 등)
- 핌플레이어 매핑: `combo_show_config`의 시퀀스 `onSuccess`(예: "linear-next"), `onFail`(예: "skip"/"retry"), 게임 output과 1:1.

## 5. 런(Run) 모드
- 타임라인을 **런**하면 배치 순서대로 진행.
- **인터랙션 박스 진입 시 팝업**: ① 진행되는 **게임 방식 설명** ② **성공 / 실패** 선택.
- 선택에 따라 **분기**(성공→씬2 등). 순서대로 끝까지 시뮬레이션.
- = 실제 테스트플레이/구동 순서를 브라우저에서 미리 걷는 **시트 시뮬레이터**.

## 5.5. 재생(▶) 버튼 — 전체화면 게임뷰 (뷰별 상이)
재생 버튼을 누르면 **전체화면으로 전환되어 실제 게임뷰만** 보인다(에디터 크롬 숨김, 현재 씬을
화면 맞춤 1920×1080으로 렌더). **ESC로 복귀.** 유니티 Play 버튼과 유사하되 **뷰에 따라 동작이 다르다**:

| 뷰 | 재생 동작 |
|---|---|
| **레이아웃 뷰** | **디자인/그리드 확인용 프리뷰.** 인터랙션/분기 없이 화면 구성만. **가변이미지박스는 상태1→상태n을 500ms마다 자동 스프라이트**(순환)로 보여줌. (그리드 오버레이 토글 가능) |
| **타임라인 뷰** | **유니티식 실제 게임 런.** §5 런 모드 = 순서 진행 + 인터랙션 박스 팝업(게임방식+성공/실패) + 분기. 가변이미지박스는 이벤트/setState로 구동. |

- 전체화면: Fullscreen API(`requestFullscreen`) + ESC 네이티브 종료(`fullscreenchange` 처리). 미지원 시 전체화면 오버레이 폴백.
- 스프라이트 속도 상수: **500ms/상태**(레이아웃 프리뷰). 재생 중지/ESC 시 원상복귀(에디터 상태 보존).

## 6. 내보내기(핸드오프)
- 타임라인 플로우 → **쇼 흐름 config**: `sequences[]`(씬/블록 순서) + 각 인터랙션의 `onSuccess/onFail` 라우팅 + 게임방식 메모.
- 코워크가 이 흐름 config를 읽어 핌플레이어 진행/분기를 구성.

## 7. QA 수용 기준 (사용자 요청: "테스트플레이·구동방식 전면 포착" 검증)
빌드 후 QA는 아래가 **모두 표현·시뮬레이션** 가능한지 확인한다:
- [ ] 대기화면(박스 배치) → 인터랙션 → 분기 → 다음 구성의 **전체 흐름**을 한 시트에 담는가
- [ ] **박스 단위**와 **씬 단위** 배치 모두 되는가
- [ ] 인터랙션의 **성공/실패 2분기**(+필요시 재시도)가 명확히 라우팅되는가
- [ ] 런 모드가 **팝업(게임방식+성공/실패)** 으로 실제 진행을 걷고, 분기가 올바른 다음 블록으로 가는가
- [ ] 여러 인터랙션·다단계 분기(씬1→성공→씬2→실패→씬2재시도 등) 시나리오가 끊김 없이 도는가
- [ ] 내보낸 흐름 config가 핌플레이어 `onSuccess/onFail`·시퀀스 순서로 **결정론적으로 해석**되는가
- [ ] Repo 자동파싱이 레이아웃 변경을 반영하는가(박스 추가/삭제 → Repo 갱신)
- [ ] 초심자(파포 페르소나)가 드래그 배치 + 인터랙션 추가만으로 흐름을 짤 수 있는가

> QA에서 위 항목 중 빠지는 게 있으면 그 부분을 보완 후 빌드. "이 타임라인 방식으로 게임 순서 시트를
> 완결"하는 것이 목표.

---

## 8. 기존 요소와의 관계
- 기존 하단 "🎞 타임라인"(연속성 트랙, 인터랙션 축)과 **개념이 다름**. 이 스펙의 타임라인 뷰는
  **진행 순서·분기 플로우 시트**. 새 상단 탭으로 만들고, 기존 하단 연속성 타임라인은 유지하거나
  이 뷰로 흡수(빌드 시 정리 — 중복 혼선 최소화).
- 씬(시퀀스>씬>박스), 이벤트(박스별 실행조건+명령), 상태(가변이미지박스)와 정합: 타임라인은
  **상위 흐름**, 이벤트/상태는 **박스 내부 동작**.
