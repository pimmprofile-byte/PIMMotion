# 고난도 10종 퍼즐 스키마 — 슬롯 배정 · 조작부 · 정답 경로

> 퍼즐 **내용**은 사용자가 작성. 이 문서는 그 내용이 들어갈 **슬롯 규격**을 고정한다.
> 기계 판독본: `cards.json`

---

## 1. 현장 사진에서 확정된 것

### 1-1. 20칸이 어디서 오는가 — 해결됨
자물쇠함 버튼 그리드가 **4열 × 5행 = 20칸**이고 행이 카테고리입니다. 그동안 "20종 카드"를 어떻게 쪼갤지가 미정이었는데, 이 그리드가 그대로 답입니다.

```
        col1   col2   col3   col4
row1  [ CHR ][ CHR ][ CHR ][ CHR ]   캐릭터
row2  [ ACC ][ ACC ][ ACC ][ ACC ]   장신구
row3  [ WPN ][ WPN ][ WPN ][ WPN ]   무기
row4  [ TOP ][ TOP ][ TOP ][ TOP ]   상의
row5  [ BTM ][ BTM ][ BTM ][ BTM ]   하의
              ↑ 저난도 ↑    ↑ 고난도 ↑
```
**고난도 10 = 각 행의 col3·col4.** 카테고리마다 정확히 2개씩이라 균등하고, 그리드 상 오른쪽이 어렵다는 규칙이 플레이어에게도 바로 읽힙니다.

### 1-2. 정답 입력 구조가 바뀝니다 (★)

앞서 "4자리 자물쇠에 입력"으로 잡았는데, 실제 장치를 보면 **경로가 문제 유형별로 갈립니다.** 그리고 20버튼 그리드는 정답 입력기가 **아닙니다.**

| 단계 | 하는 일 | 장치 |
|---|---|---|
| ① 풀이 | 퍼즐을 푼다 | 조작부 / 자물쇠 |
| ② 판정 | 정답 확인 → 함 개방 | 조작부 IN 신호 또는 물리 자물쇠 해제 |
| ③ **수령** | 해당 칸 버튼을 누른다 | **20버튼 그리드** |

**그리드를 정답 입력기로 쓰면 안 되는 이유**: 정답 공간이 20개뿐이라 찍기 확률이 5%이고, 룰렛이 이미 어느 카드를 노리는지 알려주므로 정답이 자명해집니다. **"수령 확인 + 카드 선택"** 역할이 맞습니다.

- 유효한 버튼은 **어느 순간에도 1개**뿐 → 오입력 처리가 단순(무효 + 짧은 부저)
- 조작부 문제 4종은 조작부가 곧 판정기라 **자물쇠를 안 씁니다**
- 자물쇠는 나머지 6종(이미지 3 + 테마 3)만 사용

### 1-3. 시리얼 채널이 부족합니다 (★ 조치 필요)

| 조작부 | IN 채널 |
|---|---|
| 20버튼 그리드 (직결 시) | 20 |
| 줄당기기 리미트스위치 ×2 | 2 |
| 조이스틱 4방향 + 버튼 5 | 9 |
| 왕버튼 3 | 3 |
| 아이템박스 센서 2 | 2 |
| 로딩바 토막 | 6 (가정) |
| 룰렛 휠 | 1 |
| 자물쇠 개방 감지 | 1 |
| **합계** | **44** |

Arduino Mega 표준은 **32ch(D22~D53)** 입니다. 두 가지를 같이 해야 합니다.

1. **그리드를 4×5 매트릭스 스캔으로** → 20ch가 **9ch**로 (4행+5열). 합계 33
2. **인풋보드 + 게이밍보드 2대 분리** → 시퀀스 신호(그리드·자물쇠·룰렛)와 퍼즐 조작부를 나눔.
   `device-assistant-spec.md` §8의 원래 의도(인풋보드=시퀀스 전용, 게이밍보드=게임 버튼 다수)와 정확히 맞습니다.

> 로딩바 토막 개수가 확정되면 정확한 수치가 나옵니다. 지금은 6으로 잡아뒀습니다.

## 2. 10종 배정표

요청하신 비중 그대로 — **테마 전체 3 / 이미지만 3 / 조작부 4**.

| ID | 칸 | 카테고리 | 풀이 방식 | 조작부 | 가이드 | 정답 경로 | 배정 근거 |
|---|---|---|---|---|---|---|---|
| **H01** | R1·C3 | 캐릭터 | **테마 전체** | — | G-N | 자물쇠 | 캐릭터=서사. 방을 돌며 정체를 밝히는 구조 |
| **H02** | R1·C4 | 캐릭터 | **조작부** | 줄당기기 ×2 | G-A | 줄 판정 | 줄 2개 = 순서·조합. 당겨서 캐릭터를 호출 |
| **H03** | R2·C3 | 장신구 | **조작부** | **아이템박스** | G-A | 박스 판정 | **확정 — 귀걸이.** ?상자 = 아이템 획득 은유 |
| **H04** | R2·C4 | 장신구 | **이미지만** | — | G-D | 자물쇠 | 장신구=세부 관찰 → 2장 비교형 |
| **H05** | R3·C3 | 무기 | **조작부** | 조이스틱+버튼5 | G-C | 스틱 판정 | 무기=조작. 커맨드 입력이 가장 직관적 |
| **H06** | R3·C4 | 무기 | **테마 전체** | — | G-N | 자물쇠 | 무기를 방에서 실제로 찾아오는 구조 |
| **H07** | R4·C3 | 상의 | **이미지만** | — | G-A | 자물쇠 | 단일 이미지 해독형 |
| **H08** | R4·C4 | 상의 | **조작부** | 로딩바 토막 | G-A | 토막 판정 | 끼워 맞춤 = 옷을 짜 맞추는 은유 |
| **H09** | R5·C3 | 하의 | **이미지만** | — | G-A | 자물쇠 | 단일 이미지 해독형 |
| **H10** | R5·C4 | 하의 | **테마 전체** | — | G-N | 자물쇠 | 마지막 테마형. 난이도 최상 배치 권장 |

### 조작부 배분 원칙 — 하나가 한 번씩만 주인공
| 조작부 | 배정 | 사유 |
|---|---|---|
| 줄당기기 ×2 | H02 | |
| 아이템박스 | H03 | 사용자 확정 |
| 조이스틱+버튼5 | H05 | |
| 로딩바 토막 | H08 | |
| **왕버튼 3** | **미배정** | 캐릭터 선택 전용으로 남김 |
| **룰렛 휠** | **미배정** | 룰렛 전용으로 남김 |

왕버튼과 룰렛휠을 퍼즐에 쓰지 않는 이유: 이미 **시스템 조작 의미가 붙어 있어서**입니다. 룰렛 돌리던 휠을 퍼즐 입력으로도 쓰면 플레이어가 "지금 이걸 돌리면 룰렛이 돌아가나 퍼즐이 풀리나"를 헷갈립니다. 장치 하나에 의미 하나가 원칙입니다.

### 카테고리별 균형
| 행 | 고난도 2종 유형 |
|---|---|
| 캐릭터 | 테마 + 조작부 |
| 장신구 | 조작부 + 이미지 |
| 무기 | 조작부 + 테마 |
| 상의 | 이미지 + 조작부 |
| 하의 | 이미지 + 테마 |

같은 카테고리에서 같은 유형이 두 번 나오지 않습니다. 한 카테고리를 연달아 뽑아도 지루하지 않습니다.

## 3. 유형별 슬롯 규격 (퍼즐 작성 시 이 규격에 맞춰주세요)

### 테마 전체형 (H01·H06·H10) — 화면 가이드 없음
- 게임 화면은 **"방을 조사하라"는 지시 + 타이머 + 힌트 버튼**만
- 가이드 타입 `G-N`. 이미지 에셋 **0장**
- 대신 필요한 것: 방 안에 배치할 **물리 단서물**, 힌트 3단계 텍스트
- 주의: 3종이 방 전체를 쓰므로 **동선이 겹치지 않게** 단서 위치를 분산해야 합니다. 같은 서랍에 두 문제의 단서가 있으면 순서가 꼬입니다

### 이미지만 (H04·H07·H09) — 가이드가 곧 퍼즐
| | 타입 | 미디어 규격 |
|---|---|---|
| H04 | **G-D** 2장 비교 | 745×680 × 2장 |
| H07 | **G-A** 단일 | 1520×680 × 1장 |
| H09 | **G-A** 단일 | 1520×680 × 1장 |

- 이 3종은 **이미지 품질이 곧 난이도**입니다. 압축으로 디테일이 뭉개지면 풀 수 없는 문제가 됩니다 → PNG 또는 고품질 JPEG
- 정답은 자물쇠 코드 형식(자릿수는 자물쇠 사양에 맞춤)

### 조작부 (H02·H03·H05·H08) — 가이드는 조작 방법 안내
| | 타입 | 미디어 |
|---|---|---|
| H02 | G-A | 조작 안내 이미지 1장 |
| H03 | G-A | 조작 안내 이미지 1장 |
| H05 | **G-C 영상** | 커맨드 시연 영상 (입력 순서는 영상이 훨씬 잘 전달됩니다) |
| H08 | G-A | 색 조합표 이미지 1장 |

- 판정이 조작부에서 나므로 **틀린 입력을 감지할 수 있습니다** → 이 4종만 실패 피드백(부저·적색 점멸)이 가능
- 나머지 6종은 자물쇠가 물리라 **게임이 실패를 감지하지 못합니다.** 타이머 기반 힌트만 가능

> 이게 유형별 체감 차이를 만듭니다. 조작부 문제는 즉각 반응이 오고, 자물쇠 문제는 조용합니다. 의도적으로 섞으면 리듬이 생깁니다.

## 4. 확인이 필요한 것

| # | 항목 | 왜 필요한가 |
|---|---|---|
| 1 | **20버튼 램프가 개별 제어 가능한가** | 가능하면 해금=녹 / 미해금=적으로 **진행도가 물리적으로 보입니다.** 사진의 적녹 배치가 고정 캡인지 제어 가능한 램프인지에 따라 갈립니다. 가능하면 OUT 20ch(또는 시프트레지스터)가 추가로 필요 |
| 2 | **로딩바 토막 개수** | IN 채널 총합 확정 → 보드 대수 결정 |
| 3 | **자물쇠 사양** | 다이얼 몇 자리인지 / 문자인지 숫자인지 → 이미지·테마형 6종의 정답 형식이 여기 묶입니다 |
| 4 | **자물쇠가 1개인지 20개인지** | 1개면 라운드마다 코드를 **재설정**해야 합니다(운영 동선에 영향). 20개면 그럴 필요 없지만 함이 20개 필요 |

1·2번은 장치 확인이라 바로 답이 나올 것 같고, **3·4번이 퍼즐 작성 전에 정해져야 합니다** — 정답 형식이 여기서 결정되기 때문입니다.
