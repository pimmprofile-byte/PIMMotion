# 고난도 10종 퍼즐 스키마 — 슬롯 배정 · 조작부 · 자물쇠

> 퍼즐 **내용**은 사용자가 작성. 이 문서는 그 내용이 들어갈 **슬롯 규격**을 고정한다.
> 기계 판독본: `cards.json`

---

## 1. 20칸 = 5카테고리 × 4

현장 자물쇠함 그리드가 그대로 카드 분할입니다.

```
        col1   col2   col3   col4
row1  [ CHR ][ CHR ][ CHR ][ CHR ]   캐릭터
row2  [ ACC ][ ACC ][ ACC ][ ACC ]   장신구
row3  [ WPN ][ WPN ][ WPN ][ WPN ]   무기
row4  [ TOP ][ TOP ][ TOP ][ TOP ]   상의
row5  [ BTM ][ BTM ][ BTM ][ BTM ]   하의
              ↑ 저난도 ↑    ↑ 고난도 ↑
```
**고난도 10 = 각 행의 col3·col4.** 카테고리마다 정확히 2개씩.

---

## 2. 진행 구조 — 20문제가 모두 같은 리듬 (★ 정정)

**자물쇠가 20개(카드마다 1개)로 확인되면서, 앞서 "조작부 문제 4종은 자물쇠를 안 쓴다"고 한 판정을 뒤집습니다.** 조작부 문제도 자물쇠를 거칩니다.

```
퍼즐 풀이 → 코드(또는 열쇠) 획득 → 해당 자물쇠 개방 → 함 안 버튼 누름 → 해금
```

| 유형 | 코드를 어떻게 얻는가 |
|---|---|
| 이미지만 · 테마 전체 | 퍼즐의 답이 곧 코드 |
| **조작부** | **조작부를 맞게 조작하면 코드가 드러남** (화면 표시 또는 장치 자체가 드러냄) |

즉 **조작부는 "판정기"가 아니라 "코드를 얻는 수단"**입니다. 이게 오히려 낫습니다 — 20문제가 동일한 리듬을 가지므로 플레이어가 규칙을 한 번만 배우면 됩니다. 조작부 문제만 절차가 다르면 그때마다 재학습이 필요합니다.

### 자물쇠 20개가 주는 이점
- **라운드마다 코드를 재설정할 필요가 없습니다.** 정답이 고정 상수라 config에 그대로 박힙니다
- 룰렛이 뽑은 카드의 가이드만 화면에 뜨므로, 코드를 모르는 나머지 함은 자연히 안 열립니다 → **순서 강제 장치가 따로 필요 없습니다**
- 운영 부담은 **리셋 쪽으로 이동**합니다: 다음 팀 전에 20개를 다시 잠가야 합니다 → 운영 체크리스트 필요

### 램프 제어 불가의 파장
해금 상태를 물리적으로 표시할 수 없습니다. 그래서:
- **화면 컬렉션 UI가 진행도 표시를 전담**합니다 → Phase 1에서 컬렉션 그리드의 우선순위가 올라갑니다
- 버튼이 모멘터리든 래칭이든 무관합니다. **게임이 상태를 기억**하고, 이미 해금된 칸의 중복 누름은 무시하면 됩니다
- OUT 채널이 램프에 안 쓰이므로 **연출 조명에 온전히 쓸 수 있습니다**

## 3. 시리얼 채널 — 매트릭스 스캔이면 1대로 들어갑니다

| 조작부 | 직결 | 매트릭스 |
|---|---|---|
| 20버튼 그리드 | 20 | **9** (4행+5열) |
| 줄당기기 리미트스위치 ×2 | 2 | 2 |
| 조이스틱 4방향 + 버튼 5 | 9 | 9 |
| 왕버튼 3 | 3 | 3 |
| 아이템박스 센서 2 | 2 | 2 |
| 로딩바 토막 3 | 3 | 3 |
| 룰렛 휠 | 1 | 1 |
| 자물쇠 | 0 | 0 |
| **합계** | **40** ✗ | **29** ✓ |

- 직결 40ch은 Mega 32ch을 넘습니다. **그리드 4×5 매트릭스 스캔은 필수**입니다
- 매트릭스로 하면 29ch → **보드 1대로 가능**합니다. 다만 **여유가 3ch뿐**이라 장치가 하나라도 늘면 바로 2대가 됩니다
- 자물쇠는 개방 감지를 하지 않습니다(물리 자물쇠 20개). **버튼 누름이 곧 해금 신호**입니다

## 4. 10종 배정표

요청하신 비중 그대로 — **테마 전체 3 / 이미지만 3 / 조작부 4**.

| ID | 칸 | 카테고리 | 풀이 방식 | 조작부 | 가이드 | **자물쇠** | 배정 근거 |
|---|---|---|---|---|---|---|---|
| **H01** | R1·C3 | 캐릭터 | 테마 전체 | — | G-N | **열쇠** | 방에서 열쇠를 찾아옴 |
| **H02** | R1·C4 | 캐릭터 | 조작부 | 줄당기기 ×2 | G-A | **버튼** | 당긴 순서 → 버튼 누름 순서로 변환 |
| **H03** | R2·C3 | 장신구 | 조작부 | **아이템박스** | G-A | **4자리 숫자** | **확정 — 귀걸이** |
| **H04** | R2·C4 | 장신구 | 이미지만 | — | G-D | **5자리 영문** | 2장 비교로 단어 도출 |
| **H05** | R3·C3 | 무기 | 조작부 | 조이스틱+버튼5 | G-C | **방향** | 장치와 자물쇠가 같은 언어 |
| **H06** | R3·C4 | 무기 | 테마 전체 | — | G-N | **열쇠** | 방에서 무기(=열쇠)를 찾아옴 |
| **H07** | R4·C3 | 상의 | 이미지만 | — | G-A | **4자리 영문** | 단일 이미지 해독 → 단어 |
| **H08** | R4·C4 | 상의 | 조작부 | 로딩바 토막 | G-A | **3자리 숫자** | 토막 3개 = 3자리 |
| **H09** | R5·C3 | 하의 | 이미지만 | — | G-A | **5자리 숫자** | 좌표·계산형 최고 자릿수 |
| **H10** | R5·C4 | 하의 | 테마 전체 | — | G-N | **5자리 영문** | 최종 문제. 최고 난도 |

### 자물쇠 배정 원칙 — 장치와 자물쇠가 같은 언어를 쓰게
자물쇠 8종을 **고난도 10문제에 전부 한 번씩 등장**시켰습니다(열쇠·5자리 영문만 2회). 저난도 10종은 같은 유형이 반복돼도 무방합니다 — **다양성은 고난도가 담당**합니다.

특히 궁합이 강한 3건:
- **조이스틱 → 방향 자물쇠 (H05)**: 방향으로 풀고 방향으로 잠급니다. 설명이 필요 없습니다
- **열쇠 자물쇠 → 테마 전체형 (H01·H06)**: 열쇠는 코드가 없어서 **방에서 물리적으로 찾아오는 문제에만** 쓸 수 있습니다. 반대로 테마형에는 이게 가장 자연스럽습니다
- **로딩바 토막 3개 → 3자리 숫자 (H08)**: 토막 수와 자릿수가 일치합니다

### 조작부 배분 — 하나가 한 번씩만 주인공
| 조작부 | 배정 |
|---|---|
| 줄당기기 ×2 · 아이템박스 · 조이스틱+버튼5 · 로딩바 토막 | H02 · H03 · H05 · H08 |
| **왕버튼 3** | 미배정 — 캐릭터 선택 전용 |
| **룰렛 휠** | 미배정 — 룰렛 전용 |

장치 하나에 의미 하나가 원칙입니다. 룰렛 돌리던 휠을 퍼즐 입력으로도 쓰면 "이걸 돌리면 룰렛이 도나 퍼즐이 풀리나"를 헷갈립니다.

### 카테고리별 균형
| 행 | 고난도 2종 |
|---|---|
| 캐릭터 | 테마 + 조작부 |
| 장신구 | 조작부 + 이미지 |
| 무기 | 조작부 + 테마 |
| 상의 | 이미지 + 조작부 |
| 하의 | 이미지 + 테마 |

같은 카테고리에서 같은 유형이 두 번 나오지 않습니다.

## 5. 유형별 슬롯 규격 (퍼즐 작성 시 이 규격에 맞춰주세요)

### 테마 전체형 — H01 · H06 · H10
- 게임 화면은 **지시문 + 타이머 + 힌트 버튼**만. 가이드 타입 `G-N`, **이미지 에셋 0장**
- 필요한 것: 방에 배치할 **물리 단서물**, 힌트 3단계 텍스트
- H01·H06은 열쇠 자물쇠라 **최종 산출물이 "열쇠"** 입니다 → 열쇠를 어디에 숨길지가 곧 퍼즐입니다
- H10만 5자리 영문이라 **코드를 도출하는** 구조입니다. 최종 문제이므로 앞선 문제들의 결과를 종합하는 형태도 가능합니다
- ⚠ 3종이 방 전체를 쓰므로 **동선이 겹치지 않게** 단서를 분산해야 합니다. 같은 서랍에 두 문제의 단서가 있으면 순서가 꼬입니다

### 이미지만 — H04 · H07 · H09
| | 타입 | 미디어 규격 | 자물쇠 |
|---|---|---|---|
| H04 | **G-D** 2장 비교 | 745×680 × 2장 | 5자리 영문 |
| H07 | **G-A** 단일 | 1520×680 × 1장 | 4자리 영문 |
| H09 | **G-A** 단일 | 1520×680 × 1장 | 5자리 숫자 |

- **이미지 품질이 곧 난이도**입니다. 압축으로 디테일이 뭉개지면 풀 수 없는 문제가 됩니다 → PNG 또는 고품질 JPEG
- H04·H07은 영문 자물쇠라 **답이 단어**입니다 → 5자/4자 단어가 성립하는지 먼저 정하고 퍼즐을 역산하는 게 빠릅니다

### 조작부 — H02 · H03 · H05 · H08
| | 타입 | 미디어 | 자물쇠 |
|---|---|---|---|
| H02 | G-A | 조작 안내 1장 | 버튼 |
| H03 | G-A | 조작 안내 1장 | 4자리 숫자 |
| H05 | **G-C 영상** | 커맨드 시연 영상 | 방향 |
| H08 | G-A | 색 조합표 1장 | 3자리 숫자 |

- H05만 영상입니다. **입력 순서는 정지 이미지보다 영상이 훨씬 잘 전달**됩니다
- 조작부는 IN 신호가 오므로 **틀린 조작을 감지할 수 있습니다** → 이 4종만 즉각 피드백(부저·점멸)이 가능합니다. 나머지 6종은 자물쇠가 물리라 게임이 실패를 감지하지 못하고, 타이머 기반 힌트만 가능합니다. 섞어 배치하면 리듬이 생깁니다

## 6. 로딩바 토막 — 설계 주의 (★)

토막 3개면 **순열이 6가지뿐**입니다. 찍기 확률 17%로, 고난도 문제로는 성립하지 않습니다.

> **순열 자체를 정답으로 쓰지 마세요.** 대신 **맞게 끼우면 3자리 코드가 드러나는** 구조로 가세요.

```
토막 3개를 올바른 순서로 끼움 → 각 토막의 숫자/기호가 정렬되어 3자리 코드가 읽힘
                              → 그 코드를 3자리 숫자 자물쇠에 입력
```

이러면 "맞는 순서를 찾는 과정"이 퍼즐이고 최종 정답은 자물쇠 1000분의 1이 됩니다. 6가지를 다 시도해도 **어느 게 맞는지 알 수 없다**는 게 핵심입니다 — 코드가 드러나야 비로소 알 수 있으니까요.

토막 개수가 3개가 아닌 것으로 확인되면 자릿수를 그에 맞추면 됩니다(4개 → 4자리 숫자).
