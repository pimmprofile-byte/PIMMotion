# 에셋 작업 워크플로우 — 무엇을 어떤 순서로 만들 것인가

> 질문: **퍼즐 20종을 먼저 정할까, 레이아웃·에셋을 먼저 만들까?**
> 결론: **껍데기(레이아웃·공용 에셋) 먼저. 퍼즐은 마지막.**

---

## 1. 왜 껍데기가 먼저인가

퍼즐부터 정하면 퍼즐마다 "이 퍼즐은 이런 화면이 필요해"가 나와서 **20종 × 개별 레이아웃**이 됩니다. 20개를 다 만들고 나서 규격 문제가 발견되면 20장을 다시 그려야 합니다.

껍데기를 먼저 고정하면 반대가 됩니다.

| | 껍데기 먼저 | 퍼즐 먼저 |
|---|---|---|
| 퍼즐 제작 | **규격 맞춰 병렬로 20개 동시 진행** | 하나씩 순차 (앞 결정이 뒤를 묶음) |
| 퍼즐 교체 | 이미지만 갈아끼움 | 레이아웃까지 재작업 |
| 유니티 빌드 | **리스킨 = config+에셋 교체, C# 0줄** | 퍼즐마다 신규 처리 → C# 증식 |
| 규격 오류 발견 시 | 1장 재작업 | 20장 재작업 |

배경도 같은 원칙(판 먼저, 내용 나중)으로 갔고 잘 나왔습니다. 같은 논리입니다.

### 껍데기 고정의 핵심 = 가이드 슬롯 4타입

퍼즐 20종이 전부 같은 화면을 쓸 수는 없습니다(모스부호는 영상, 틀린그림은 2장 비교). 그렇다고 20종이 다 다르면 껍데기가 아닙니다. **4타입이면 20종이 다 들어갑니다.**

| 타입 | 구성 | 미디어 규격 | 쓰는 퍼즐 |
|---|---|---|---|
| **G-A** 단일 | 이미지 1장 | 1520×680 | 대부분 (심볼사전·연산·논리 등) |
| **G-B** 3스텝 | 이미지 3장 가로 | 480×680 × 3 | 순서배열 · 다단복합 |
| **G-C** 영상 | 동영상 1개 | 1520×680 / mp4 | 모스부호 · 음계리듬 · 점멸 |
| **G-D** 2장 비교 | 이미지 2장 좌우 | 745×680 × 2 | 틀린그림 · 오버레이 |

**지금 정할 것은 이 4타입뿐입니다.** 어떤 퍼즐이 어느 타입인지는 나중에 골라도 됩니다.
프레임은 4장만 만들면 되고, 퍼즐 20종은 그 안에 들어갈 **이미지 파일**이 됩니다.

### Phase 2 · 유니티 1라운드 검증 — **게이트 (★ 반드시 통과 후 진행)**

껍데기만으로 **더미 1라운드**를 유니티에서 돌립니다. 카드는 1장, 퍼즐은 아무 이미지, 보상은 더미.

- [ ] 시리얼 IN → 시퀀스 진입
- [ ] 룰렛 스핀 → 카드 1장 결과
- [ ] 가이드 화면 4타입 각각 표시
- [ ] 함 버튼 IN → 팝업 등장 → 배지·텍스트 자리 정합
- [ ] 컬렉션 1칸 채워짐 → 커스터마이즈 착용
- [ ] 배경 `persist` 유지되는지 (깜빡임 0)
- [ ] TextMesh가 빈 명판에 정확히 앉는지 → **실측값으로 좌표 확정**

> **이 게이트가 이 워크플로우에서 제일 중요합니다.** 여기서 규격을 확정하지 않고 Phase 3·4로 가면
> 오류가 **20배로 증폭**됩니다. 껍데기 1세트 고치는 것과 보상 20종·퍼즐 20종을 고치는 것의 차이입니다.

### Phase 3 · 보상물 20종 *(Phase 2 통과 후)*

- [ ] 난이도 검수 — 이지 10 / 하드 10 실제로 갈리는지 플레이테스트

## 3. Phase 3 착수 전에 정해야 할 것 — 캐릭터 착장 구조 (★)

분류에 **상의·하의**가 있다는 건 캐릭터에 **레이어드 착장**이 있다는 뜻입니다. 이건 캐릭터 아트 제작 방식을 통째로 가릅니다.

| | 옵션 A · 통짜 + 오버레이 | 옵션 B · 파츠 분리 (권장) |
|---|---|---|
| 캐릭터 아트 | 완성된 전신 1장 | **기본 착장 상태의 베이스 1장** |
| 악세서리 | 위에 얹는 오버레이 | 슬롯별 레이어 (장신구/무기/상의/하의) |
| 상의·하의 교체 | **불가** (밑에 옷이 이미 그려져 있음) | 가능 |
| 작업량 | 적음 | 많음 (캐릭터 10종 × 파츠 정합) |
| 조합 수 | 제한적 | 10 × 4슬롯 = 조합 폭발 |

**상의·하의를 분류에 넣은 이상 옵션 B여야 합니다.** 옵션 A로 가면 상의 악세서리를 해금해도 갈아입힐 데가 없습니다.

옵션 B로 갈 때의 규격 — Phase 3 시작 전에 고정해야 합니다:
- 캐릭터 베이스는 **기본 속옷/내의 상태**로 그림 (그 위에 상의·하의가 올라감)
- **공통 캔버스 + 고정 기준점**: 캐릭터 10종이 전부 같은 크기 캔버스(예: 400×760)에, **어깨선·허리선·손 위치가 동일 픽셀**에 오도록. 이게 어긋나면 악세서리가 캐릭터마다 따로 놀아서 **10종 × 10악세서리 = 100조합을 손보정**해야 합니다
- 레이어 순서(z): 배경 < 하의 < 캐릭터 몸 < 상의 < 장신구 < 무기
- 악세서리는 **캐릭터와 같은 400×760 캔버스에 알파 PNG**로 (오프셋 계산 불필요 = 정합 오류 0)

> 이 "공통 캔버스 + 고정 기준점" 규칙 하나가 Phase 3의 성패를 가릅니다.

## 4. 병렬 진행 가능 구간

```
Phase 0 배경  ─┐
Phase 1 껍데기 ─┴─▶ Phase 2 검증 게이트 ─┬─▶ Phase 3 보상 20종 ─┐
                                        └─▶ Phase 4 퍼즐 20종 ─┴─▶ Phase 5 연출 ─▶ Phase 6 핸드오프
```

- **Phase 0과 1은 병렬** — 배경은 판이고 껍데기는 그 위라 서로 안 기다립니다
- **Phase 3과 4는 병렬** — 보상물과 퍼즐은 서로 무관합니다
- **Phase 2는 직렬 게이트** — 여기만 반드시 혼자 통과해야 합니다

## 5. 지금 당장 정할 것 / 나중에 정해도 되는 것

| 지금 정해야 | 나중에 정해도 됨 |
|---|---|
| 가이드 슬롯 **4타입 규격** | 어떤 퍼즐이 어느 타입인지 |
| 캐릭터 **착장 구조**(옵션 A/B) + 공통 캔버스 규격 | 캐릭터 10종의 이름·외형 |
| 악세서리 **분류 4종** (완료: 장신구·무기·상의·하의) | 악세서리 10종의 구체적 아이템 |
| 팝업·카드·배지 **레이아웃** | 팝업에 들어갈 설명 문구 |
| 자물쇠 **자릿수**(4자리 가정) | 20종의 실제 정답값 |
| 시리얼 IN/OUT **채널 배정** | 물리 배선 |

> 오른쪽 열은 **전부 config 값**입니다. 나중에 바꿔도 에셋 재작업이 없습니다.
> 왼쪽 열은 **규격**이라 바뀌면 에셋을 다시 그려야 합니다. 그래서 지금 정합니다.
