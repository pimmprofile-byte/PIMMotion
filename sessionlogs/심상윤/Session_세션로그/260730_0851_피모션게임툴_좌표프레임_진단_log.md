## 2. 진단 (코드 근거 · PIMM_UnityGameCreator.ver1.14 + pimm-handoff SKILL)

### 2-1. 툴이 실제 내보내는 것 (v1.14, `buildLayoutJSON`/`encodeHandoffBox`)
레이아웃 JSON 최상위: `sequenceId, phaseId, seqLabel, resolution:[1920,1080], background, bgm, prefabs[], scenes[](각 boxes[]), interactions[], boxes[](활성씬·하위호환)`.
박스 1개(`encodeHandoffBox`)가 담는 것:
- `index,id,type,x,y,w,h`(정수·1920×1080 좌표), `opacity,locked,hidden`, **`unity`**(앵커 min/max = Y-flip 반영 완료), `role`
- 이미지/프리팹/텍스트별 필드(`subtype,assetId,states,defaultStateId,activeStateId` 등) — **assetId** 사용
- `span`(인터랙션 구간), **`continuity`**(persist/change/enter/exit), `crossSceneId`
- **`clip`**(+`unityMask`: RectMask2D/SpriteMask), **`crop`{x,y,w,h 0..1}**(+`cropUnity`: spriteRect)
- **`frameType`**(cropframe/fullframe/framegraphic) + **`frameTypeUnity`**(fit 힌트) + framegraphic이면 `ratioLock,frameSrcW/H`
- `prompts[]`, `events[]`

→ **결론: 현재 툴은 이미 fit 정보(frameType/frameTypeUnity/crop/cropUnity/unity앵커/resolution)를 전부 내보낸다.**

### 2-2. 세 프레임 모드의 '실제 렌더 fit' (에디터 정본, line 3930-3933)
- **cropframe(기본)**: `object-fit: cover` (박스 채우고 넘침 중앙크롭). 버튼은 `contain`. `crop` 지정 시 그 영역만.
- **framegraphic**: `object-fit: fill`(100%×100%). 박스를 이미지 원본비율로 재생성(ratioLock)하므로 fill이어도 **왜곡 0**.
- **fullframe**: 이미지=1920×1080 전체, (-x,-y)로 위치. 박스=콘텐츠영역 표시.

### 2-3. 이정민 문제의 근본원인 (2겹)
1. **오래된 export 사용**: ROULETTE_NEW_layout.json에 `assetFile` 필드가 있고 frameType/crop/clip/unity가 없음. **현재 툴은 `assetFile`을 안 쓰고 `assetId`를 씀** → 그 파일은 **프레임 파이프라인(v1.12+) 이전의 구 export**. 그래서 유니티가 fit을 추측(preserveAspect stretch/contain) → 어긋남.
2. **좌표/프레임 개념 미이해**: 박스는 1920×1080 좌표. 박스 크기와 다른 비율의 에셋을 만들고 프레임모드를 안 쓰면 어긋남. 해결책이 곧 **cropframe/framegraphic/fullframe** (대표 지시 그대로).

### 2-4. ★ 스킬/힌트의 진짜 gap (이게 코워크가 설명 못한 이유)
- **cropframe의 fit이 `cover`라는 게 어디에도 명시 안 됨.** 에디터는 cover로 렌더하지만:
  - export `frameTypeUnity`(cropframe) = `{fit:"boxSprite", note:"박스 W×H 스프라이트를 앵커 위치에 배치"}` — **"cover/중앙크롭" 단어 없음**.
  - pimm-handoff SKILL §3 cropframe 행 = "박스 W×H 스프라이트를 anchor 위치에" — **역시 cover 명시 없음**.
  - → 유니티 개발자는 Image 컴포넌트 기본(preserveAspect=false=stretch, 또는 true=contain)으로 떨어짐. **cover가 안 나옴.** 이정민이 겪은 바로 그 버그.
- 버튼 cropframe은 에디터에서 `contain`인데 이것도 힌트에 없음.
- **정정 필요**: cropframe = **object-fit:cover(중앙크롭 채움)**, crop 있으면 그 rect, 버튼은 contain. Unity 매핑 = **Sprite.Create에 박스비율 맞춘 중앙 crop rect**(이정민이 낸 해법과 동일) — 공용 헬퍼로 GameRoulette/GameBoxSort/GamePIMMotion이 공유(preserveAspect 재발 방지).

### 2-5. 부차 gap
- **읽기 누락(보고8)**: 코워크가 sceneNote·박스 메모·prompts·인터랙션 메모를 한 번에 안 읽고 바로 적용 → 대표 지시("먼저 json 스터디→적용순서 제시"). 스킬 §6이 있지만 **"적용 전 전체 메모/노트 완독 + 적용순서 제안"을 강제 게이트로** 승격 필요.
- **플러그인 배포본 vs repo 스킬 동기화**: 대표 말대로 플러그인 유니티 스킬이 패치된 적 없음 → repo `pimm-handoff`(개념은 대부분 있음)와 배포본 차이 가능. 동기화 + 위 cropframe=cover 명시가 핵심.

### 2-6. 잠정 결정 후보 (대표 합의 대기 — 아직 확정/내보내기 아님)
- (A) pimm-handoff 스킬 §3에 **fit 열(cover/fill/fullscreen) 명시** + cropframe=cover(+crop/버튼 예외) + Sprite.Create 중앙크롭 헬퍼 레시피 + preserveAspect 금지 경고.
- (B) 툴 export `frameTypeUnity`(cropframe) note에 "object-fit:cover(center-crop)" 문구 추가(선택, 다음 단계).
- (C) 스킬에 **'적용 전 완독+스키마 스터디+적용순서 제안' 강제 게이트** 추가.
- (D) 현장 즉시조치: 이정민에게 **현재 v1.14로 재export**(구 assetFile 파일 폐기) 안내 + 프레임모드 선택 가이드(박스맞춤=cropframe / 이미지원본=framegraphic / 배경=fullframe).
